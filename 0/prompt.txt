2. Key Technical Concepts:
   - **Architecture:** Nexus has a TS CLI and agent (`cli/src`), a Rust core (`harness-core`) and a Ratatui live TUI (`core/src/bin/nexus_tui`). They communicate over sidecar NDJSON protocol v1 (`cli/src/protocol.ts` ↔ `protocol.rs`).
   - **Continuation:** `maxSteps` is now a segment. The `ContinuationBudget` defaults are maxTotalSteps 300, maxTurnMinutes 120, stagnationSteps 12, maxRecoveries 2, maxCompletionNudges 2. It is enabled via `buildConfig`; `--no-continuation` turns it off.
   - **New TurnReasons:** STEP_BUDGET_EXHAUSTED, TIME_BUDGET_EXHAUSTED, STAGNATION_DETECTED, REQUIREMENTS_INCOMPLETE.
   - **Objective ledger (`core/objective.ts`):**
     - Verbatim objective plus seeded requirements with full bodies (`detail`).
     - The pinned block is injected at request time via `requestMessages()` and is never stored or compacted.
     - Tools: `update_requirements` and `read_objective` (agent-level only, not in HARNESS_TOOLS, which keeps the byte-parity test DEDUP-003 intact).
     - Only the operator can accept a descoping (`/requirements accept`); `/requirements clear` replaces the objective explicitly.
     - `verified` binds a passing verifier attempt on the current inputs; any mutation demotes it.
   - **Verifier attempts:** keyed by candidate identity, process epoch, mutationSeq and an external-inputs fingerprint. A prior failure is reused only if all of these match.
   - **Steering:** `steer` command and `steer.ack` event (queued/applied/deferred/cancelled/rejected/duplicate). Deferred steering becomes a follow-up turn. TUI ids carry a per-process prefix. The ledger dedupes across restarts.
   - **File diffs:** per-operation before/after snapshots with a Myers diff (`file_diff.ts`); `file.diff` events with a preview of ≤40 lines; the full diff is in the evidence ledger.
   - **Paste buffers:** private-use placeholder characters (U+F0000+n); Ctrl+O view, Ctrl+X expand, Backspace remove; burst fallback when bracketed paste is unavailable.
   - **Doctor:** schema v2, exit codes 0/1/2/3, layered endpoint checks. Repairs go through `safe_fs.ts`: ancestry validation, O_NOFOLLOW plus a `/proc/self/fd` real-path and dev/ino check, then `fchmod`. The lock and manifest are created exclusively and verified.
   - **Persistence:** stable tool-call ids are `call_<sha256:12>`. History completeness is tracked, with an archive in `<session>.history.jsonl`.
   - **npm EALLOWSCRIPTS root cause:** `~/.npmrc` `allow-scripts` is re-exported as `npm_config_allow_scripts` under `npm test`. The gate now uses `env -u` and `npm audit --json`; SCAN-005 marks scanner failure, SCAN-004 marks findings.
