## PR #19 (10i, resource contract): CHANGES REQUIRED

Every task-controlled spawn is routed through `spawnContained`:
- setup commands
- candidate agent
- black-box oracle
- legacy hidden and regression checks
- agent version probe

The remaining `spawnSync` calls in `run.mjs` and `workspace.mjs`, and the one in `isolate.mjs`, are trusted. I found no uncontained path. `node --check` passes on `resources.mjs` and `cgroup_supervisor.mjs`.

I also checked these and found them sound:
- **Escape from the cgroup:** the bwrap sandbox mounts no `/sys`, so the payload cannot write `cgroup.procs`, including in the same-uid dev case.
- **fd 3 leak:** a local experiment shows the report fd does not reach the payload.
- **Running before the limits apply:** the shell joins the payload cgroup before `exec`.

Blockers:
1. `eval/README.md`, "Resource contract" bullet 2 — the claim "the agent's writes stay charged after it exits" is false, and the storage bound is overstated. When a scope is removed, the kernel reparents tmpfs charges to the parent cgroup, where nothing limits them.
   - **Failure scenario:** the agent fills about `memoryBytes` of tmpfs and exits. The hidden and regression phases each get a fresh `memory.max` and can write another `memoryBytes`. Total retained storage is about 3x `memoryBytes` or more, bounded only by the tmpfs default of 50% of RAM.
   - **Fix:** mount the `workspaceRoot` tmpfs with an explicit `size=` and have preflight verify it (`statfs` blocks, not only the magic number). Then reword the README: "per-phase charge, plus a hard tmpfs size cap".
2. `eval/resources.mjs`, `kill()` (about line 66) — a kill that arrives before the shell has joined the payload leaf is lost. `cgroup.kill` on an empty leaf succeeds and returns, and the payload then starts unkilled. The report arrives before `spawn`, so overflow or timeout handling could hit this window.
   - **Failure scenario:** `kill()` is called right after the cgroup path is reported. The cgroup kill hits an empty leaf and the 10s fallback is cleared. The payload runs to natural exit, and `close` never fires until then.
   - **Fix:** have the supervisor emit a second `{joined:true}` line after the shell joins the payload cgroup. Until then, `kill()` should also SIGTERM the supervisor, and the supervisor should check a "stop requested" flag before spawning. Or make `kill()` retry the cgroup write until `populated 0`.

Non-blocking:
3. `eval/cgroup_supervisor.mjs`, `finish` — SIGKILL or OOM of the supervisor leaves the payload orphaned until the harness `close` handler runs `cgroup.kill`. Fail-closed holds, since there is no report, but nothing restricts the payload in the meantime. The fallback `process.kill(-pid)` misses setsid'd processes. Fix: the harness fallback should always write `cgroup.kill` as well.
4. `eval/cgroup_supervisor.mjs:~35` — `memory.max` read-back differs when `memoryBytes` is not a multiple of the page size. Fix: validate `memoryBytes % 4096 === 0` in `resourceConfigProblem`.
5. `memory.oom.group` is not set. An OOM kill of a validator child can make a check fail rather than error. Fix: set `memory.oom.group=1` and treat `oomKills&gt;0` in hidden or regression phases as a containment error.
6. `cli/test/eval_integrity.test.ts` — the new test asserts `qualificationResourceIsolationProblem({resources: ok}) === null`, so it hard-fails on any host without a user systemd manager. Fix: gate it on an env flag, as the CI step does.
