**Blockers**

1. **`hardened_check.mjs:143-155`, modified baseline data files cross over unchecked.**
   - Any changed baseline file crosses unless its path is in `BLOCKED`. Go `testdata/**/*.golden`, Jest `__snapshots__/*.snap`, `fixtures/`, `snapshots/` and similar are not blocked.
   - **Failure scenario:** the agent edits a golden or snapshot file so it matches its own, wrong output. The hidden test compares against the agent's file and passes.
   - Fix: block `testdata/`, `fixtures/`, `__snapshots__/`, `snapshots/`, `golden/`, `*.golden`, `*.snap`, `testutil*/`, `testing/`, `__mocks__/`, `mocks/`, `e2e/`, `*.setup.*` and `setupTests.*`. Prefer a rule that only source-extension files may change, plus a small manifest allowlist.

2. **`hardened_check.mjs:149-153`, the copy writes through symlinks in the fresh workspace.**
   - `walk` skips symlinked directories in the agent's tree. But the destination write follows symlinks in the fresh tree.
   - **Failure scenario:** a baseline repository has a symlinked directory or file. The agent replaces it with a real directory or file and puts content there. `mkdirSync` and `writeFileSync` follow the fresh symlink and write outside the check workspace, as the operator.
   - Fix: before every write or delete, `lstat` each path component under `freshWs` and refuse if any is a symlink. Also refuse any destination that is a symlink or collides with `fresh.links`.

3. **A vacuous pass is still possible when tests are silently skipped.**
   - `hardened_check.mjs:95-102` lets `Cargo.toml` `[package]` and `[features]` change. `autotests = false`, `build = …` or a changed `default` feature set can make `cargo test` run zero hidden tests and exit 0.
   - The same class exists for deleted files (point 4). The check passes on exit status alone.
   - Fix: reject `autotests`, `autobenches`, `build`, `links` and `[features] default` changes. Add a per-task `expectedTests` or canary requirement, so a run that executed fewer tests than the oracle ships counts as a failure.

4. **`hardened_check.mjs:156-161`, deleting baseline config is allowed.**

   - Fix: refuse deletion of any manifest or config file the `testConfigChange` list recognises. Treat a deleted manifest as a config change.
