1. **BLOCKER – `core/src/file_ops.rs` (`edit_file`, `delete_file`) vs `cli/src/core/capabilities.ts:467–490` and the `edit_file` schema (~268–295): the new arguments are not in the tool schemas.**

   - Fix: add both parameters to the schemas, or make the error text not mention parameters the model cannot see.
   - `docs/USER_MANUAL.md:217` still says "fuzzy recovery".

2. **BLOCKER – `cli/src/tester.ts:24–31`: the test-filter sanitizer allows newlines, so the cargo path still injects commands.**
   - The allowlist includes `\s`, which matches `\n` and `\r`.
   - Reproduced: `detectTestCommand(&lt;Cargo.toml dir&gt;, "foo\ntouch /tmp/pwned")` returns `cargo test -- foo\ntouch /tmp/pwned`. The cargo branches (lines 45 and 49) interpolate the filter unquoted.
   - Fix: replace `\s` with a literal space, `[A-Za-z0-9_:./ -]`. Also forbid a leading `-` so a filter cannot become a flag.

3. **BLOCKER – `cli/src/core/capabilities.ts:787`: `run_tests` is now `mutating: true`.**

   - The `candidateMutation` hook at `cli/src/agent.ts:743–752` then runs `mutationSeq++`, `invalidateVerified`, `setUnverifiedChanges(true)`, clears `verificationEvidence`, and increments `turnMutations`.
   - So a model-invoked passing `run_tests` demotes verified requirements and marks the turn as having unverified changes. A test-only turn can no longer end as `NOT_REQUIRED`.
   - I found this by reading the code and did not run a probe.
   - It also makes `run_tests` prompt for approval, because `agent.ts:2574` now uses `cap.mutating`.
   - Fix: keep `mutating: true` for the read-only gate only. Add a separate flag (for example `mutatesCandidate: false`) that the spine uses for `candidateMutated`. Alternatively, exempt `test_discover_run` the way `orchestration` is exempted at line 744.

6. **SHOULD-FIX – `cli/src/workspace_trust.ts`: nothing can grant trust.**

7. **SHOULD-FIX – `cli/src/tester.ts:236–290` (`isVerifierDeliverableBound`) is both too strict and too loose.**
   - Too strict:
     - Rust inline `#[cfg(test)]` tests never count. For a change to `file_ops.rs` with `cargo test`, the command does not name the file and there is no `*_test` file, so the result is REGRESSION_FREE forever.
     - A root-level `test_foo.py` is not matched by `isTestPath`.
     - Non-test verifiers such as `tsc --noEmit`, a build, or `./check.sh` always downgrade.
   - Too loose:
     - Step 3 returns true if any test file contains the changed file's stem. A common stem such as `index`, `agent` or `utils` almost always matches.
     - Steps 2 and 3 never check that the matching test actually ran.
   - Cost: step 3 does a synchronous read of every test file, up to depth 4 with no size cap, per verification and per `run_tests` call.
   - Fix: bind on the output evidence (test names or paths reported as run) plus an explicit allowance for ecosystems with inline tests. Cache the scan and bound it by size.

8. **SHOULD-FIX – `cli/src/tester.ts:200–204`: `isFilteredVerifierCommand` and `hasExecutedTests` have gaps and false positives.**
   - Not detected as filtered: `go test -run=X`, `node --test --test-name-pattern=x`, `make test FILTER=foo` (the pattern needs trailing whitespace), `pytest a.py::test_b`, and positional `cargo test name`.
   - False positive: `git diff -- src` is flagged as filtered.
   - `hasExecutedTests` returns true for `0 passed; 0 failed; 0 ignored; 0 measured; 12 filtered out`.
   - Fix: match `-run[= ]`, `--test-name-pattern`, `FILTER=\S`, `::`, and positional arguments for known runners. For the zero-pass case, require `passed &gt; 0`.

9. **SHOULD-FIX – `cli/src/core/egress.ts:~238`: the broadened generic secret regex redacts ordinary code.**
   - It now allows an optional opening quote and a bare `auth`. I measured these:
     - `password = process.env.DB_PASSWORD` classifies `process.env.DB_PASSWORD`.
     - `secret = os.environ["X"]` classifies `os.environ[`.
     - `auth = require("./auth")` classifies `require(`.
     - `password: Optional[str]` classifies `Optional[str]`.
     - `self.auth_token = REDACTED classifies `self._generate_token()`.
   - Each matched value is then `replaceAll`'d over the whole text, which corrupts code shown to the model and in telemetry.
   - It also raises false quarantines on `search_web` and `fetch_web`.
   - Fix: restore the required quote, or require the value to contain no `(`, `[`, `.` or `)` unless quoted. Drop bare `auth`.
   - The new environment-variable secrets have the same flaw: any value of 8+ characters in a variable whose name contains `SECRET`, `PASSWORD` and similar is replaced everywhere. Add a minimum length of about 16, exclude path-like values, and skip common words.

10. **SHOULD-FIX – `cli/src/ui.ts:6–15` with `cli/src/sidecar.ts:338`: `redactSecrets` is now heavy and runs per streamed delta.**
    - It runs the full `redactForTelemetry` pipeline (environment enumeration, a pass over all patterns, and entropy tokenization) for each `assistant.delta`.
    - I measured about 0.4 ms per call, on a 96-variable environment under load. Note that `sidecar.ts` is outside the stated scope.
    - Fix: for deltas, keep the cheap regex-only path and redact fully at message end.
    - Deltas also split tokens, so full redaction per delta gives weaker protection anyway.

11. **SHOULD-FIX – `core/src/runner.rs:214–235`: bounded drain discards all output on timeout.**
    - If a reader does not finish within 500 ms, for example because a backgrounded `server &amp;` holds the pipe, `Vec::new()` replaces the whole stdout or stderr. Everything already read is lost.
    - It also calls `terminate_process_tree`, which adds up to 500 ms of SIGTERM grace and kills the daemon.
    - `drain_timeout` can be 0 when `remaining_time` is 0, which loses output from a command that finished right at the limit.
    - Fix: have the reader threads share an `Arc&lt;Mutex&lt;Vec&lt;u8&gt;&gt;&gt;` and return whatever has been collected. Compute the drain as a floor, not `min(remaining, 500ms)`.

12. **SHOULD-FIX – `core/src/file_ops.rs:89–154` (`write_file_atomically`): several behaviours change.**
    - **Cleanup:** the temp file is not removed if `verify_descriptor_confinement` or `write_all` fails, which leaves `.name.tmp_atomic.&lt;ns&gt;` files in the workspace.
    - **Read-only files:** a file with mode 0444 in a writable directory can now be edited. The old in-place open failed. Check `meta.permissions().readonly()` first.

    - **Permission window:** `set_permissions` is applied after the content is written, so a restrictive mode is applied late.
    - **Temp name:** it uses a timestamp only. Add a counter or random suffix.

13. **SHOULD-FIX – `core/src/file_ops.rs:~610–650` (`edit_file`): "exact match only" is not what is implemented.**
    - The trim fallback, `norm_orig.contains(trimmed_old)`, still matches sub-token substrings. `old="x = 1\n"` matches inside `x = 10`, and the result becomes `x = 20`.
    - `line_by_line_trim_match` ignores indentation, and the replacement uses the model's indentation.
    - In a file with mixed endings, `has_crlf` converts every `\n` to `\r\n`, including untouched LF lines.
    - The exact-match branch inserts a bare `\n` into a CRLF file when the match is single-line but the replacement is multi-line.
    - Fix: require line boundaries for the trimmed match, and normalise line endings per line.

14. **SHOULD-FIX – `cli/src/core/authority.ts:~128` and `cli/src/tools.ts:~482`: the `--pre` check is not applied in the bridge's read-only gate.**
