## Generator approach
- **How it works:** it opens `cli/tsconfig.json` through `typescript/unstable/sync`, resolves `SidecarEvent`, `SidecarCommand` and `PROTOCOL_VERSION` in `src/protocol.ts`, and walks the checker's types. Nothing is hand-written or regex-parsed.

- **Descriptions:** JSDoc on types and properties is carried into `description`.
- **Determinism:** definitions, properties, `required`, enum values and variants are all sorted. Two consecutive runs gave the same sha256 (`b2747ba8…b66a`), and the file contains no absolute paths.
- **Unsupported types:** a function, a TS enum, or a tuple with optional or rest elements stops the generator with an error naming the property.
- **`--check`:** exits 1 naming the file when the schema is stale, and also when the ledger is stale.

API calls it depends on:
- `API({cwd})`, `updateSnapshot({openProjects})`, `Snapshot.getProjects`, `Project.checker`

## Parity design

- **Samples:** the generator reads the checked-in schema and writes a minimal and a full sample per message. It adds one extra full sample per alternative where a field is a union of shapes, so every `ApprovalReview` kind is covered. `--check` and a TypeScript test fail on drift, and every sample validates against the schema.
- **Events, TS to Rust:** `schema_samples_parse_as_their_own_event_variants` parses every event sample with `parse_event` and rejects `Event::Unknown` and `Review::Unknown`.
- **Event type sets:** the Rust event names must equal the schema's, with no allowlist needed. The Rust names are read from the `#[serde(rename)]` attributes via `include_str!`, because Rust cannot list enum variants; the test asserts every variant carries a rename.
- **Event fields:** top-level field names are taken from the derived `{:#?}` output. Rust may read no field the schema lacks, and the schema fields Rust does not read must equal `EVENT_FIELDS_NOT_READ` exactly (11 events, mostly `turn_id`). This is what makes a new optional TS field fail on the Rust side. It checks top-level fields only; nested structs are covered by parsing, not by field accounting.
- **Commands, Rust to TS:** I took the checked-in fixture route. `rust_commands_are_the_checked_in_fixture_and_published_commands` asserts the fixture is byte-for-byte what `encode_command` produces for one representative of every variant (`provider.connect` with and without its optional fields). `protocol_parity.test.ts` validates each line against the schema and requires `parseCommand(line)` to equal the line minus `v`, which also catches a renamed optional field.
- **Command sets:** the representatives must equal the scanned `Command` variants, which must be a subset of the schema's commands; the remainder must equal `COMMANDS_NOT_SENT = ["answer"]`.
- **Why this route:** no stdout plumbing between test runners, no new dependency, and each language's own test fails with a precise message. The cost is two test-only introspection tricks (source scan and Debug-format parsing). The alternative was `cfg_attr(test, derive(Serialize))` on production types, which is outside the allowed edit area.

## Input contract

- **`--input-json &lt;file|-&gt;`:** reads `{ "schema_version": 1, "task": "&lt;text&gt;" }`. It must be a JSON object, `schema_version` exactly 1, `task` a non-empty string (trimmed).
- **Authority:** only `task` is read. I mapped no other member onto options.
- **Plain stdin:** read as the task only when there is no argument, no `--input-json`, no `--resume` or `--fork-session`, and stdin is not a terminal.
- **Bounds:** 1,048,576 bytes and valid UTF-8; larger input is rejected, not truncated.
- **Usage errors (exit 2):** argument plus `--input-json`, an invalid document, an unreadable file, or empty stdin. The message goes to stderr and stdout stays empty.
- **With `--resume`:** `--input-json` is allowed and supplies the prompt, as an argument does today.

## 3. CLI contract

```
nexus verify [--worktree &lt;path&gt; | -w &lt;path&gt;] [--base &lt;ref&gt;] [--head &lt;ref&gt;]
             [--verifier &lt;cmd&gt;] [--deliverable-file &lt;path&gt;]... [-y|--yes | --approve-verifier &lt;sha256&gt;]
             [--approve-verification-edit &lt;path&gt;]... [--review] [--objective &lt;text&gt;|--objective-file &lt;f&gt;]
             [--timeout-secs &lt;n&gt;] [--receipt &lt;file&gt;] [-j|--json]
```

- **Modes.** `--worktree` alone verifies the working tree against `HEAD`, or against `--base`. `--base` with `--head` verifies two commits. In both cases both trees are materialised into scratch directories so the caller's checkout is never written.
- **Why scratch directories.** `prepareBaselineTestsCopy` writes under `&lt;workspace&gt;/.nexus/verify/` (`independent_check.ts:785`). Run it on the scratch head, not the user's tree.
- **Verifier selection.** `--verifier` gives source `configured`. Otherwise discover from the base tree, never the head. A discovered verifier needs `-y` or `--approve-verifier &lt;digest&gt;` (the `describeVerifier` digest); otherwise the verdict is BLOCKED with the command and digest printed. This mirrors headless review mode (`spine_handlers.ts:201-203`).
- **Reviewer.** Off by default. `--review` requires a configured model and an objective; with no model the verdict is BLOCKED (`review_unavailable`). Without `--review` the receipt records `review: NOT_RUN`.

**Verdict rules** (computed outcome, then mapped; the reviewer and guard can only lower):

| Verdict | When | Exit |
|---|---|---|
| VERIFIED | Outcome `VERIFIED`: passed, tests executed, definition bound, deliverable-bound, and configured or independent. No unapproved guard finding. With `--review`, the reviewer said ACCEPT. | 0 `ok` |
| REGRESSION_FREE | Outcome `REGRESSION_FREE` | 2 `unverified` |
| UNVERIFIED | No applicable verifier, zero tests executed, or an empty diff (`NOTHING_TO_VERIFY`) | 2 `unverified` |
| UNVERIFIED | Outcome `NOT_ESTABLISHED`: verifier or enforced type-check failed or timed out; or the reviewer said REJECT | 1 `failed` |
| BLOCKED | Verifier not approved; an unapproved verification-config edit or detected weakening under mode `approve` or `block`; an untrusted checkout (`trustedGitArgs` throws); `--review` without a model; incomplete scan bounds | 3 `blocked` (new) |
| usage or bad ref | | 2 `usage` |
| SIGINT | | 130 |

- An empty diff is not 0. `run` gives `NOT_REQUIRED` → 0, but here the caller chooses the base.

## 4. Security analysis for G-3

**Trust model to document.** The process launcher (argv and env) is the operator. The repository content, especially the head, is untrusted. VR-1 cannot defend against a hostile launcher; it can make every verdict-affecting input visible in the receipt. So structure the core as `verifyChange(request, operatorContext)`, with the request limited to worktree, base and head, so VR-2 can expose only the request.

| Attack | Existing protection | VR-1 must add |
|---|---|---|
| Head redefines the verifier (`package.json` test script, Makefile, conftest) | `snapshotVerifierDefinition` and `verifierDefinitionChangedSince` (`independent_check.ts:183, 601`); the agent refuses at `spine_handlers.ts:140-168` | Discover and bind from base; a definition change is never VERIFIED and is a guard finding |
| `--verifier 'echo ok'` or fabricated output | `hasExecutedTests` (zero tests → UNVERIFIED); deliverable binding by imports in pre-existing tests, not by output text (`tester.ts:1785-1790`); inline programs are unbindable (`independent_check.ts:106`) | Record the verifier source and digest in the receipt. Residual risk: a launcher-supplied script that prints a fake runner summary |
| Weakened, skipped or deleted test | The independence rule (section 1) | Run base tests against head code; add an explicit weakening finding (section 5) |
| Repository policy relaxes the guard | `off`, `record` and `allow` are honoured only when trusted (`security.ts:229`) | Load policy from the base scratch directory; record `NEXUS_TRUST_WORKSPACE` |
| Env: `NEXUS_TYPECHECK=off`, timeout, passthrough, `PATH` | Verifier env scrub; `toolSha256` (`tester.ts:174`) | Record the names that were set; with `--strict-env`, refuse `NEXUS_TYPECHECK=off` (decision) |
| Base chosen so the diff is empty, or base equals head | None | `NOTHING_TO_VERIFY`, exit 2; the receipt binds base and head commits and trees; the action takes base from the event |
| Symlinks or a planted `.git` | `trustedGitArgs` (`git.ts:40`); symlink refusal in snapshots (`independent_check.ts:204`) and in `isSafeWorkspaceFile` (`tester.ts:990`) | Materialise without following links that leave the tree |

## 7. Risks and open decisions

1. **Base environment parity.** A bare base checkout has no installed dependencies, so the base run fails for environmental reasons and fakes a fail-before. Default: materialise base as a copy of the head worktree with tracked files replaced by base content and dependency directories symlinked (the pattern at `independent_check.ts:787-830`). Treat exit 126 or 127, or zero tests at base, as "no baseline" (REGRESSION_FREE at most).
2. **Verifier failure.** Verdict UNVERIFIED, but which exit code? Default: 1, matching `run`'s `NOT_ESTABLISHED`.
3. **What BLOCKED covers.** Default: approval needed, unapproved config edit or weakening, untrusted checkout, reviewer unavailable. A plain modification of an existing test is recorded only; the independence rule already caps it.
4. **Weakening heuristic.** It is regex-based and will misfire. Default: findings always appear in the receipt, and `--approve-verification-edit &lt;path&gt;` clears BLOCKED but never restores VERIFIED.
5. **Discovered verifier without `-y`.** Default: BLOCKED with the digest, as in `run`.
6. **Reviewer default.** Default: off, `--review` opt-in, REJECT → UNVERIFIED with exit 1, ACCEPT never raises. Whether the reviewer may have tools (a full read-only turn) is deferred. The single-call client API (`cli/src/client.ts`) was not read.
7. **Receipt persistence and id for VR-2.** Default: slice 1 prints it and writes `--receipt &lt;file&gt;`; a durable store is decided with VR-2. Hash-chaining through `linkRecord` is optional, by import only.
8. **Ladder duplication.** Default: new pure function plus parity test now, and ask the `run_turn.ts` owner to adopt it.
9. **Sandbox for hostile test code.** Default: document that verify runs repository code with the caller's privileges; add `--sandbox` in slice 3 after reading `wrapSandboxedCommand`.
10. **Flag to let REGRESSION_FREE exit 0.** Default: no.
11. **Lines not read.** `independent_check.ts:230-590` (snapshot internals) was only skimmed by grep; confirm its behaviour on a scratch-directory base before slice 1.
