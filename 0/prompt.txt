## Generator approach
- **How it works:** it opens `cli/tsconfig.json` through `typescript/unstable/sync`, resolves `SidecarEvent`, `SidecarCommand` and `PROTOCOL_VERSION` in `src/protocol.ts`, and walks the checker's types. Nothing is hand-written or regex-parsed.
- **Named types:** any alias or interface declared under `cli/src` is emitted once under `$defs` and referenced by `$ref` (36 shared definitions, including `TurnResult`, `ApprovalReview`, `ReceiptSection`, `CatalogProvider`, `CatalogModel`, `ModelRef`).
- **Descriptions:** JSDoc on types and properties is carried into `description`.
- **Determinism:** definitions, properties, `required`, enum values and variants are all sorted. Two consecutive runs gave the same sha256 (`b2747ba8…b66a`), and the file contains no absolute paths.
- **Unsupported types:** a function, a TS enum, or a tuple with optional or rest elements stops the generator with an error naming the property.
- **`--check`:** exits 1 naming the file when the schema is stale, and also when the ledger is stale.

API calls it depends on:
- `API({cwd})`, `updateSnapshot({openProjects})`, `Snapshot.getProjects`, `Project.checker`
- `Checker`: `resolveName`, `getDeclaredTypeOfSymbol`, `getTypeOfSymbol`, `getPropertiesOfType`, `getPropertyOfType`, `getNonNullableType`, `isArrayType`, `isTupleType`, `getTypeArguments`, `getSignaturesOfType`, `getIndexInfosOfType`, `typeToString`
- `Type`: `flags`, `value`, `getTypes`, `getAliasSymbol`, `getAliasTypeArguments`, `getSymbol`, `isClassOrInterface`, `getTypeParameters`, `getTarget().elementFlags`
- `Symbol`: `name`, `id`, `flags`, `declarations[0].path`, `getDocumentationComment`
- Enums: `TypeFlags`, `SymbolFlags`, `SignatureKind`, `ElementFlags`

Fragility is moderate. The export is named "unstable" and it spawns the bundled tsgo binary, so a TypeScript minor bump could rename something. That would show up as a thrown error or a drift failure rather than a silently wrong schema, and the TypeScript calls are confined to this one file. A run takes about 1 s.

## Decisions for you
1. **Two golden records do not match the types.** In `protocol_v1_golden.jsonl`, `hello` lacks the required `commands` and `tool.end` lacks the required `evidence`. I left the shared fixture alone and the schema strict. The test lists these two as known gaps that must fail for exactly that reason, so the list can only shrink; every other record validates. The alternatives are adding the two fields to the fixture (the Rust test would need a run) or making them optional in the type. Say which you want.
2. **XERJ was not queried.** I read your "no network calls" as covering the localhost node, so the PR's "Reference coding" section still needs that query or an "XERJ unavailable" line.
3. **`additionalProperties` is never `false`,** for commands as well as events, because `parseCommand` drops unknown fields. It appears only for an index signature. The README explains this.
4. **`models.catalog` is flattened.** The `{type, id} &amp; Catalog` intersection becomes one object variant, so `Catalog` itself has no `$defs` entry, though its members do. `Pick&lt;SlashSpec, …&gt;` in `hello.commands` is inlined the same way. An `allOf` with a `$ref` to `Catalog` is possible if you prefer it.
5. **Tuples needed an extra keyword set.** `ReceiptRow = [string, string]` is emitted as `prefixItems` with `minItems` and `maxItems` of 2, so the validator supports those three keywords beyond your list. The validator throws on any keyword outside its subset.
6. **Top level is `anyOf`, not `oneOf`.** `tool.detail` and `receipt` exist in both directions, so an event of either type would also match the command schema.
7. **The schema filename follows `PROTOCOL_VERSION`** (`sidecar-v&lt;N&gt;.schema.json`).
8. **Not registered in the unit tier.** The shard runner discovers `test/*.test.ts` on its own, so nothing was required. I did not add the test to `UNIT_FILES` in `test_tiers.mjs` or to `test_durations.json`; it runs in about 2 s and spawns tsgo, so it would fit if you want it there.
9. **No flow wiring.** There is no existing `check_*` step in the `cli/package.json` scripts or the Makefile that this obviously belongs to, so I added none and edited no workflow. The test is the CI gate; a standalone `node cli/scripts/gen_protocol_schema.mjs --check` step in `ci.yml` would be your edit.
