Baseline: `origin/main` at `c8e986f4f02da37b35a1c26e46f31daf16a506c2` (2026-11-21). This file maps selected, source-backed controls to their enforcement code, relevant tests, and provenance. The checker verifies that referenced files exist and that rule IDs used in code or tests have a row; the listed test files are evidence pointers, not a claim that each test has been executed for this revision. It replaces no other document: `docs/EXECUTION_CONVERGENCE.md` describes the spine, and `docs/v1.2.0/SEMANTIC_AND_ARCHITECTURAL_INTEGRITY.md` describes acceptance gates.

How to read a row: **Enforced in** names the implementation boundary. **Test evidence** points to relevant automated tests; it does not imply a test run unless the run is separately recorded. **Why** records the incident or audit finding that motivated the control. Controls that remain advisory or lack direct evidence are listed as gaps below rather than credited as implemented.

## Decided

- **Intent-record write failure stays fail-open, by decision (2026-11-17, resolving EI-1).** When the write-ahead record of a call cannot be written, the call still runs, because refusing every tool on a full or failing disk would stop all work while the workspace is still writable. It is never silent: a notice is emitted, the turn result carries `persistence.durable = false` with the failure text, and an operation unit whose turn is not durable is failed for the operator (`operation_runner_execution.ts`, "persistence failure"), so a degraded record cannot be accepted as a clean result. Pinned by `cli/test/durable_continuity.test.ts` ("durable-write failures ... are reported through reportPersistenceFailure"). Revisit only if a run must be provably recoverable after every call; that is a different mode, not a silent default.

- **The start record is already fsynced (EI-2, closed: audit premise disproved).** The state store writes a temporary file, fsyncs it, renames it, and fsyncs the containing directory; relevant coverage is in `cli/test/durable_continuity.test.ts`. The previously measured local cost was about 3 ms per synced write; this is a historical measurement, not a current performance guarantee.
- **Spine hooks `processLifecycle`, `contextAdmission`, `evidenceEmission` stay no-op in production (EI-7, decided 2026-11-17).** They are extension seams for tests and embedders. Receipts reach the operator through the observer and the flight recorder, and context admission is decided in the agent; wiring them would add a second path for the same evidence. Deleting them would change a tested interface for no demonstrated failure. The hooks the agent depends on (`authorityAdmission`, `egressQuarantine`, `candidateMutation`) are installed in production.
- **Task-state arrays are not normalised on load; the downstream guards stay (EI-7, decided).** Removing a guard needs a proof that no stored shape reaches it; none was found cheaper than the guard.
- **No document claims a tamper-evident audit log (checked 2026-11-17).** The "immutable" wording in `docs/PHASE2_RECONCILED_REQUIREMENTS.md` is about candidate and invocation identities, which the code keeps stable; it is not a claim of a hash-chained log. Nexus does not have one, and none of its documents should be read as promising it.

## Known gaps (recorded, not fixed here)

|---|---|---|
