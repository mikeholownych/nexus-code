## Roadmap and compatibility notes

- v1.3 PA-1, PA-2 and PA-3 already cover parallel visibility, verified integration and goal semantics. PA-4 stages this assignment against those units and the active WP-P10-02 durable-budget work.
- Operation records are versioned and reject records from a newer schema ([operation_schema.ts](../../cli/src/core/operation_schema.ts)). PA-1 resource reservations use schema v4; old records remain readable and schedule serially when their prior parallel declarations lack reservations.
- XERJ definition-first lookup identified `TeamOrchestrator`, `WorkUnitSpec`, `newOperation` and the existing dependency-cycle check. The first batch-spec package reuses the operation parser and constructor; no orchestration code was copied.
- No provider, gateway, or homelab-ai change is part of the workstream.

## Implementation progress (2026-11-21)

- `/batch` uses operation specifications and the existing `OperationStore`, `ConvergenceScheduler`, and `OperationRunner`; it defaults to sequential execution. Parallel admission requires isolated worktrees and, as of PA-1 resource-admission work, explicit per-operation CPU/memory reservations. This adds no second scheduler or persisted workflow store.
- `/batch` is wired into the sidecar slash router and REPL, so the TUI obtains its completion/help entry from the same slash catalogue. The implemented actions are `run`, `validate`, `status`, `list`, `pause`, `resume`, `cancel`, and `results`. Pause writes the durable `PAUSED` status at a safe boundary. `/loop` and `/goal` lifecycles remain unimplemented.
- Regression tests cover quoting/Unicode, workspace and symlink boundaries, sequential execution, durable state, partial aggregation, CPU/memory admission and legacy serial fallback. The PA-1 slice passed 44 focused operation/batch tests, 28 operation release/review tests, and the CLI TypeScript build in its isolated worktree. These are targeted results; they do not replace the prescribed full-suite qualification. No provider code changed.
- A definition-first XERJ lookup in the `opencode` corpus found `packages/schema/src/goal.ts:11` (MIT) with bounded round count, stall count, and boot identity fields. This informed the roadmap comparison only; no peer code was copied. The corpus is flagged as incompletely indexed, and the listed `goose` corpus was unavailable.
- This is an implementation checkpoint, not completion evidence for PA-4. Authority enforcement, prompt-only runtime compatibility tests, distinct pause semantics, `/loop`, `/goal`, full batch terminal-state persistence, adversarial coverage, interface-level behavior tests, minimal-provider workflow fixtures, independent review, and comparative evaluation remain outstanding.
