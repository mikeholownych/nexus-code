## Roadmap and compatibility notes

- v1.3 PA-1, PA-2 and PA-3 already cover parallel visibility, verified integration and goal semantics. PA-4 stages this assignment against those units and the active WP-P10-02 durable-budget work.
- Operation records are versioned and reject records from a newer schema ([operation_schema.ts:26](../../cli/src/core/operation_schema.ts#L26), [operation_schema.ts:59](../../cli/src/core/operation_schema.ts#L59)). Lifecycle additions must use that migration gate rather than reinterpret old records.
- XERJ definition-first lookup identified `TeamOrchestrator`, `WorkUnitSpec`, `newOperation` and the existing dependency-cycle check. The first batch-spec package reuses the operation parser and constructor; no orchestration code was copied.
- No provider, gateway, or homelab-ai change is part of the workstream.

## Implementation progress (2026-11-21)

- The operation specification is now the validation format for `/batch`: `batch_spec.ts` delegates key validation to `validateOperationSpec` and dependency/cycle validation to `newOperation`. `batch.ts` maps the accepted spec to `DurableOperationState` and drives the existing `OperationStore` and `OperationRunner`; batches default to sequential execution, and parallel admission requires the existing isolated-worktree option. This adds no second scheduler or persisted workflow store.
- `/batch` is wired into the sidecar slash router and REPL, so the TUI obtains its completion/help entry from the same slash catalogue. The implemented actions are `run`, `validate`, `status`, `list`, `resume`, `cancel`, and `results`. `pause` is listed only as a staged interface and currently returns an explicit unsupported-state response; there is no separate durable `PAUSED` operation status yet. `/loop` and `/goal` lifecycles remain unimplemented.
- Regression tests were added for quoting/Unicode, workspace and symlink boundaries, sequential execution, durable state, and partial aggregation. They have **not** been run: the shared `SUITE` claim is still present, its recorded PID is absent, and repository concurrency rules do not permit breaking it before 24 hours. `npm --prefix cli run build` passed on the exact worktree after installing the locked CLI dependencies with `npm ci --ignore-scripts`; no provider code changed.
- A definition-first XERJ lookup in the `opencode` corpus found `packages/schema/src/goal.ts:11` (MIT) with bounded round count, stall count, and boot identity fields. This informed the roadmap comparison only; no peer code was copied. The corpus is flagged as incompletely indexed, and the listed `goose` corpus was unavailable.
- This is an implementation checkpoint, not completion evidence for PA-4. Authority enforcement, prompt-only runtime compatibility tests, distinct pause semantics, `/loop`, `/goal`, full batch terminal-state persistence, adversarial coverage, interface-level behavior tests, minimal-provider workflow fixtures, independent review, and comparative evaluation remain outstanding.
