# Nexus Code v1.0.0-rc.13 release candidate

**Maturity:** release candidate; prerelease, not stable.

**Status:** this candidate is for exact-artifact qualification. It does not establish independent acceptance or authorize stable v1.0.0 promotion. Qualification results must identify the workflow-produced package and its digest.

This release packages the Nexus Code Linux x86-64 client: the TypeScript CLI and sidecar, production Node dependencies, Rust `harness-core`, and Ratatui `nexus-tui`. It replaces RC12, which was tagged but never published: its release workflow failed in the test step, so no RC12 package exists. RC13 ships the same product changes as RC12; everything in the [RC12 notes](v1.0.0-rc.12.md) and the [RC11 notes](v1.0.0-rc.11.md) is included.

## Changes since RC12

### Release workflow (not in the package)

- The release job now prepares the same evaluator environment as CI before it runs the test suite: the pinned Go toolchain, the pinned evaluator toolchains, and removal of the hosted runner's preinstalled SDK trees. RC12's release run failed without them (`go: command not found`, and `compiler exposure could not be checked; refusing qualification`). A test now fails if the release and CI workflows disagree on this setup.

No product code changed between RC12's tag and RC13.

## Runtime requirements

- Linux x86-64 with glibc 2.35 or newer.
- Node.js 22 or newer.
- An OpenAI-compatible inference endpoint, local or explicitly selected provider.

The archive does not include Node.js. Rust and Cargo are not required at runtime. No other OS or architecture is claimed.

## Candidate assets

The release workflow for `v1.0.0-rc.13` is expected to produce the version-matched Linux archive, `SHA256SUMS`, SBOM, notices, installer, and provenance. The workflow run, tag commit, artifact digests, and qualification evidence must be recorded before this candidate can be accepted. Local builds are not interchangeable with the workflow-produced artifacts.

## Qualification status

This is a candidate, not an accepted release. The installed-RC gates — platform and lifecycle evidence including the power-loss cell, mandatory automated CI PTY (§5.1) and scripted installed-RC PTY (§5.2), provider and standalone qualification, held-out task quality, cross-runner reproducibility, independent exact-RC acceptance and the requirements ledger — remain outstanding for this artifact. RC11 evidence does not carry over to RC13 without an explicit, reviewed carry-forward. The manual matrix (§5.3) is waived for v1.0.0 by DEC-20; this does not waive steering, accessibility, or any other release gate. Passing source CI does not satisfy installed-RC qualification.
