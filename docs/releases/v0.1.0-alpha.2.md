# Nexus Code v0.1.0-alpha.2 alpha release candidate

**Maturity:** alpha, pre-1.0 SemVer prerelease.

**Status:** candidate prepared; no GitHub Release has been published.

This is the second 0.x alpha. Like `v0.1.0-alpha.1`, it is not a stable release; install it by pinning `NEXUS_VERSION=v0.1.0-alpha.2` after publication.

This package is the complete Nexus Code Linux client: TypeScript CLI/sidecar, production Node dependencies, Rust `harness-core`, and Ratatui `nexus-tui`.

## Changes since v0.1.0-alpha.1

### Long tasks and compaction (73489bd)

- **No default step or time ceiling.** The 300-step / 120-minute defaults are gone. A turn continues across durable segment checkpoints while it makes progress, and stops on completion, cancellation, demonstrated lack of progress, a failure, or a step/time limit you set explicitly (`--max-total-steps`, `--max-turn-minutes`). Delegated helpers (`spawn_subagent`) no longer take a step allowance; its `max_steps` argument was removed.
- **State-aware repetition.** A repeated action is judged against the workspace state it ran on: an unchanged failing command on an unchanged workspace is a loop; polling backs off instead; plan edits are not progress. Tracking is persisted per objective and survives compaction, follow-up turns and restart.
- **Durable compaction.** Each compaction is committed in order (archive, task state, session) with fsync; recovery ignores uncommitted archive entries. A compaction that cannot be written stops the turn as `PERSISTENCE_FAILED`. `/compact` issued during work is queued and runs at the next settled step.
- **Provider capabilities and token accounting.** Context size and output allowance are discovered from the provider's `/models` when advertised (homelab-ai gateway, vLLM). When the gateway offers `/v1/tokenize`, Nexus counts the exact request body it is about to send; counts are labelled by source. `--strict-token-count` requires a provider count. Standalone servers keep working on client estimates.

### Replies cut off at the output limit (d19fb29)

A reply that reaches the output allowance (`finish_reason=length`) no longer ends the turn the first time. Nothing from it runs; the model is told which call was cut off and to write the content in parts, and the turn continues. A second cut-off reply in a row ends the turn as `INFERENCE_FAILED`, as before.

### Other

- Cloudflare contest demo and CI documentation updates.
- `scripts/installer-smoke.sh` now derives its upgrade-test version from the version under test, instead of a fixed `v0.1.0-alpha.2` that would have collided with this release.

## Known limits

- Live validation was against the homelab-ai gateway only; no live run against another OpenAI-compatible server.
- Counting equivalent to the gateway's admitted request is not available from the current gateway contract (see the [gateway capability handoff](../reviews/2026-10-13-homelab-ai-gateway-capability-handoff.md)); pre-dispatch counts are labelled as counts on a sampled worker.
- Recovery from a cut-off reply is covered by scripted tests; whether a given local model then writes the content in parts has not been observed live.

## Runtime requirements

- Linux x86-64 with glibc 2.35 or newer.
- Node.js 20 or newer.
- An OpenAI-compatible inference endpoint, local or explicitly selected provider.

The archive does not include Node.js. Rust and Cargo are not required at runtime. No other OS or architecture is claimed.
