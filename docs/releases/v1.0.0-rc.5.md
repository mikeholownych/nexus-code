# Nexus Code v1.0.0-rc.5 release candidate

**Maturity:** release candidate; prerelease, not stable.

**Status:** this candidate is for exact-artifact qualification. It does not establish independent acceptance or authorize stable v1.0.0 promotion. Qualification results must identify the workflow-produced package and its digest.

This release packages the Nexus Code Linux x86-64 client: the TypeScript CLI and sidecar, production Node dependencies, Rust `harness-core`, and Ratatui `nexus-tui`.

## Changes since RC4

- An explicit `--read-only` launch cannot be lowered to `auto` during the session. Folder trust only enables project instructions and integrations; an unset approval mode defaults to review in every workspace.
- Read-only REPL sessions refuse mutating slash commands such as `/init`, `/skill init`, `/commit`, `/upgrade`, and `/mcp add`. TUI `/test` follows verifier approval policy and can be cancelled with Escape.
- Upgrade archive extraction uses a trusted system `tar` with ambient `TAR_OPTIONS` cleared, preventing PATH shims or environment options from executing during extraction.
- RC reproducibility runs use the package builder from the reviewed workflow revision while keeping product source bound to the peeled RC tag, and verify the builder identity and bytes.
- Upgrades fail closed when `NEXUS_VERIFY_ATTESTATION=1` and no trusted GitHub CLI is available. The installer now verifies provenance by default through `/usr/bin/gh` or `/usr/local/bin/gh`; setting `NEXUS_VERIFY_ATTESTATION=0` explicitly skips that check.
- Corrects SSRF and locality classification for IPv6 NAT64 addresses. The well-known NAT64 prefix is checked against its embedded IPv4 destination, and the local-use NAT64 prefix is rejected.
- Automated commits never include Nexus-managed `.nexus/` state, even when it was previously staged or ignore rules would expose it, including the first commit in a new repository.
- Git-backed candidate identity also excludes `.nexus/` runtime state, so session and checkpoint writes do not appear as source progress or prevent stagnation detection.
- Protects saved MCP server configuration that may contain credentials: the configuration directory and file use owner-only permissions, writes are atomic, and malformed or invalid existing configuration is preserved instead of being overwritten. Save failures are reported to the user.
- Bounds `file_info` line counting to 8 MiB while retaining a fixed 1 KiB binary probe. Larger files still return metadata without full line-count scanning.
- Caps CST symbol and outline reads at 8 MiB; workspace scans skip oversized files, while direct symbol and outline requests return an error. Parsing walks borrowed lines with a bounded nine-line signature lookahead, avoiding millions of per-line allocations on newline-dense files at the size limit.
- Bounds `edit_file` and `patch_file` whole-file reads to the same 8 MiB limit. Oversized targets are left unchanged and receive a clear error.
- Makes Linux package archives reproducible across supported build runners by creating them with the pinned release builder, removing host-specific archive metadata differences.
- Corrects the cross-runner workflow's pinned artifact-download action so the exact published-candidate comparison can execute.

The REPL PTY cleanup and T4 evaluator supervisor changes improve qualification-harness reliability and do not change product behavior. In particular, containment cleanup after a task process exits no longer leaves a repeating timer behind. These source changes and their CI results do not replace RC5 artifact checks, cross-runner qualification, or installed-package qualification.

## Runtime requirements

- Linux x86-64 with glibc 2.35 or newer.
- Node.js 22 or newer.
- An OpenAI-compatible inference endpoint, local or explicitly selected provider.

The archive does not include Node.js. Rust and Cargo are not required at runtime. No other OS or architecture is claimed.

## Candidate assets

The release workflow for `v1.0.0-rc.5` is expected to produce the version-matched Linux archive, `SHA256SUMS`, SBOM, notices, installer, and provenance. The workflow run, tag commit, artifact digests, and qualification evidence must be recorded before this candidate can be accepted. Local builds are not interchangeable with the workflow-produced artifacts.
