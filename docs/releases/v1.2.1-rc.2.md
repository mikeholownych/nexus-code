# Nexus Code v1.2.1-rc.2 (release candidate)

**Maturity:** release candidate. Supersedes [`v1.2.1-rc.1`](v1.2.1-rc.1.md); the previous stable release is [`v1.2.0`](v1.2.0.md). This candidate carries the whole v1.2.1 scope and the stable release notes ([`v1.2.1.md`](v1.2.1.md)) together, because the release workflow requires a stable tag to be a version-only commit directly on its release candidate.

**Why rc.2 exists:** the release workflow for `v1.2.1-rc.1` failed in its CLI suite step and published no archive. One test (`cs4_shell_audit`, "exit 127 on runTestSuite names the scrub and the passthrough setting") assumed the verifier hint lists a given variable among at most twelve sorted names; on the release runner more than twelve toolchain-looking variables sort before it, so the test failed. The test is skipped wherever `/usr/bin/cargo` exists, which is why pull-request CI never ran it. The product behaviour is unchanged (the hint deliberately shows at most twelve names); the test now removes the other candidate variables before it checks. Version tags are never moved, so the fix ships as a new candidate.

What changed and what did not: see [`v1.2.1.md`](v1.2.1.md). Plan and per-unit status: [`docs/v1.2.1/PLAN.md`](../v1.2.1/PLAN.md).

Live-gateway tool-call validity for this candidate is recorded in the evidence file under [`docs/evidence/v1.2.1/`](../evidence/v1.2.1/) once measured (a measurement is only valid for the archive it was taken on). Until that file exists, no claim about it is made.
