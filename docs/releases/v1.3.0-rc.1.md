# Nexus Code v1.3.0-rc.1 (release candidate)

**Maturity:** release candidate. Supersedes nothing; the previous stable release is [`v1.2.2`](v1.2.2.md). **External qualification is pending.** This is not a claim that Nexus Code is frontier-grade. Every test, review and measurement named here is internal validation, and results are reported as measured, including open findings. Inventory of each gate and unit, with the review record: [`v1.3.0-READINESS.md`](v1.3.0-READINESS.md) ("ledger closed for the landed units, qualification pending"). The candidate was assembled from `release/v1.3.0` tip `da83ebb12` (merge of #822); the readiness inventory's "RC cut state" section records the candidate commit and the CI results measured on it.

Theme (from [`docs/v1.3.0/PLAN.md`](../v1.3.0/PLAN.md)): let other programs drive Nexus and let teams govern it, without weakening the gate. Every new surface goes through the same approval and verification gates as the terminal. Experimental surfaces are marked experimental below and in their documents.

## What is new, by track

- **Protocol and embedding.** The sidecar protocol has generated JSON Schemas, a published document and version negotiation (PF-1, `docs/PROTOCOL.md`, #697 #700 #712). `nexus run --json` has a versioned result contract and documented exit codes (PF-2, #705). A library entry point and an embedding guide (PF-4, `docs/EMBEDDING.md`, #779 #786; not published to npm). Experimental: `sidecar.js --listen` accepts other clients on a private unix socket with a token, as controller or read-only observers (PF-3, #797).
- **IDE access.** `nexus acp` serves the supported subset of ACP v1 over stdio; client permission answers can approve one pending action and nothing else (AC-1, `docs/ACP.md`, #740 #741 #752). Conformance fixtures recorded from Zed 1.29.3 and CodeCompanion.nvim 20.3.0, no live model (AC-2, `docs/evidence/AC2_ACP_CONFORMANCE.md`, #749); those captures predate later ACP changes.
- **Verification layer.** `nexus verify` gives a verdict (VERIFIED, REGRESSION_FREE, UNVERIFIED, BLOCKED) on a change without running an agent (VR-1, #707). The same check is available to other harnesses through an MCP tool and ACP `_nexus/verify`; the caller cannot raise the verdict (VR-2, `docs/evidence/v1.3.0/VR2.md`, #756 #777). Sandbox denials are recorded as receipt and flight events and never raise a verdict (VR-3, #745).
- **Governance.** Managed policy with precedence system, user, project; restrict-only; a parse error in the system or user tier fails closed; `nexus policy show|check` (GV-1, `docs/MANAGED_POLICY.md`, #717 #738 #778 #783). Admin strict mode and MCP/plugin allowlists (GV-5). `nexus audit export|verify` bundles with a hash manifest, optional ed25519 signing (GV-2, `docs/AUDIT.md`, #714 #771 #772). A hash-chained flight recorder checked on replay (GV-3, #696 #701 #761). Telemetry transparency and an opt-out (GV-4, `docs/TELEMETRY.md`, #695).
- **Hooks and plugins.** `pre-tool` and `post-tool` command hooks that can deny a call and never approve one (HK-1, `docs/HOOKS.md`, #782 #805). Plugin packages with a `nexus-plugin.json` manifest, installed from a local directory and verified against an install receipt: `nexus plugins install|list-installed|remove|verify` (HK-2, #796). Per-plugin approval for workspace plugins, workspace manifest plugins that run as subprocesses, one terminal-safe sanitiser at every plugin, hook and doctor print site, and a serialised trust-store lock (HK-3, partial, `docs/PLUGINS.md`, #798 #808 #810 #822).
- **Background, scheduled and event-driven runs (experimental, Linux).** A detached runner and `nexus job`/`nexus runner` (BG-1, `docs/RUNNER.md`, #780). `nexus schedule` with `--cron`, `--every`, `--at`, each run an unattended job in a fresh worktree (BG-2, `docs/SCHEDULES.md`, #799 #801 #802). Event triggers: a workspace `.nexus/triggers.json` whose exact bytes you approve fires read-only unattended jobs on a file change or on a signed loopback webhook through `nexus runner serve --webhook-port`; rate limits, quarantine, a loop guard, receipts naming the trigger; `nexus triggers list|approve|revoke|status|release|fire-test` (BG-3, `docs/TRIGGERS.md`, #803 #812).
- **Parallel agents, goals and budgets.** `nexus operation watch` and worktree owner receipts, resource admission (PA-1, #787 #794). Merge arbitration that re-verifies the merged tree (PA-2, #785 #788 #790). Goal semantics: a goal from a dead process resumes paused, fingerprint stall counting, completion only by a verifier receipt, an optional token budget (PA-3, `docs/v1.3.0/PA3_ACCEPTANCE.md`, #758 #775 #789 #806 #809 #811). `/batch` runs a validated dependency graph on the operation engine (`docs/v1.3.0/BATCH.md`). An operation active-time budget bounds the aggregate active wall time of an operation (default and maximum 4,320 minutes), pauses it on expiry and shows elapsed and remaining time in `nexus operation status`; `nexus operation budget <id> --max-total-active-minutes <n>` changes it (WP-P10-02 partial, #823). `/goal`, `/loop` and `/team` are in the command catalogue; `/goal` and `/loop` are staged, see "In this candidate, and out of it".
- **Sandbox and tools.** Named sandbox profiles `--sandbox :workspace|:read-only|:network`, shown in `nexus doctor`, the REPL, the TUI and the sidecar `session.state`, and carried by sandbox-denial records (SB-1, `docs/SANDBOX_PROFILES.md`, #781 #795 #814 #816). One tool registry binds each spec to its handler; the dispatch function is split into admission, decision, confirmation and execution phases with the same order (MT-2, `docs/TOOL_REGISTRY.md`, #784 #804 #817 #818 #819 #820).
- **Language servers and CI.** LSP lifecycle, bounds, position encodings and project roots (LS-1, LS-2, #718 #733 #736 #739 #751). CLI suite shard fan-out under stable required check names (#742 #743 #746 #748 #750).

## Behaviour changes that need a migration note

1. **Workspace JavaScript plugins need per-file approval (HK-3).** A plugin in a workspace's `.nexus/plugins/` or `plugins/` loads only when its exact bytes were approved with `nexus plugins trust <file>` in a terminal. `nexus trust` alone no longer loads it; nothing is approved on upgrade. An approved plugin runs from a private copy of its one file, so imports of sibling files or workspace packages fail and the plugin shows `load-failed`. A workspace plugin cannot take a name of your own plugin. Your own plugin directories (`~/.nexus/plugins/`, `~/.config/nexus/plugins/`) are not loaded when Nexus starts in a directory that contains them (your home), and `plugins list` and `nexus doctor` say when an operator directory was skipped. First session prints a notice; `nexus doctor` warns `plugins.workspace`; a changed approved plugin gets a stronger notice. Names printed by plugin, hook and doctor commands are escaped, so a name with control characters shows as `\uXXXX`. **Approved workspace plugins still run in the Nexus process with full authority; that mode is deprecated and subprocess execution is planned for v1.4.** If a process dies while it holds the trust-store recovery guard, trust-store writes stop with an actionable error until you check that no recovery is running and remove that guard. Migration table: `docs/PLUGINS.md` "Migrating workspace plugins". (#798 #808 #810 #822)
2. **Project hooks accept only an allowlisted command shape and run from verified copies (HK-1).** A project's `.nexus/hooks.json` command must be one of the listed forms (an explicit interpreter with a workspace script, or a script with an absolute `#!` line); `env`, `npm run`, `make`, inline code (`-c`, `-e`), other launchers are refused and the file is invalid. Approval records SHA-256 of the script and the files given to it; the hook runs from a private copy of those bytes under `~/.nexus/hook-runs/`, so `$0`, sibling imports and sourced files do not lead back to the repository. Approving needs a person at a terminal. Hooks that need anything else belong in `~/.config/nexus/hooks.json`. (`docs/HOOKS.md`, #782 #805)
3. **A name in `mcp.allow` no longer admits a workspace-defined server (GV-1).** A bare name does not pin the command; a workspace `.mcp.json` entry of that name is refused. Use `command:` or `url:` entries or `mcp.disable_workspace = true` for a boundary. `nexus policy check <file>` validates a policy before rollout; exit code 2 means Nexus would refuse to start. (`docs/MANAGED_POLICY.md`, #778 #783)
4. **A broken system or user policy file fails closed.** Nexus refuses to start (exit 2) and names the file and tier. `/etc/nexus/policy.toml` is the system tier.
5. **Unattended jobs and schedules.** They never approve a command or a network call and have no allow-always; the only command that runs without approval is the exact operator `--verifier`, in the sandbox, in the run's worktree (it runs repository and model-written code without a prompt). A `read-only` run does not run its verifier and says so (`verifier.status: NOT_RUN`). A schedule needs a trusted workspace (`nexus trust`) that is checked again at every slot. (`docs/SCHEDULES.md`, `docs/RUNNER.md`, #780 #799 #802)
6. **Schedules are UTC with a 5-minute floor.** `--cron` and `--at` are UTC, `--every` is 5 minutes to 30 days, cron slots must be at least 5 minutes apart, there is no time zone and no `@daily`. Missed runs are counted and reported; `--on-missed report` (default) runs nothing, `run-once` runs one catch-up job. At most 64 schedules.
7. **`--listen` socket (experimental).** Refused under auto approval; the socket is mode 0600 in a 0700 directory; the socket server refuses a caller-supplied directory that others can enter; the token comes from a 0600 descriptor file; the sidecar refuses a socket directory inside the workspace; under `--sandbox` the directory is hidden from commands. A client cannot grant allow-always or change the mode. Protocol stays 1 (new error codes `UNAUTHORIZED`, `NOT_CONTROLLER`, `NOT_PERMITTED`). (`docs/PROTOCOL.md`, #797 #814)
8. **Goal pause semantics (PA-3).** A goal whose recorded driver (pid, host, kernel start time, boot id) is not a live process on this host resumes `PAUSED` with a reason, on the read path and the drive path. Records from builds before `activeStartTicks` pause. `/team` and `nexus operation` are no longer experimental. Known gap: an unattended job or loop `prepare` can override a stale pause (#807). (`docs/v1.3.0/PA3_GOAL_LIFECYCLE.md`)
9. **Operation records are schema v8 (WP-P10-02, #823).** The first write by this build migrates an older record forward; a byte-identical `.pre-migration-vN` copy is kept. A build that predates v8 refuses a v8 record ("upgrade Nexus to open it"); do not share operation state with an older build. Every operation now has an active-time cap (4,320 minutes) shared across its running units; a legacy record's age is used as a conservative estimate of time already spent. The operation view schema gains `activeBudget` (additive).
10. **`--sandbox` masks the task-state directory and pins its ancestors.** A state path through a symlink inside the workspace, or a workspace that is the state directory, is refused with an explicit error (PA-3, #811). The agent's file tools refuse `~/.nexus/tasks`.
11. **Sandbox profiles (SB-1).** `--sandbox :read-only` sets the approval mode like `--read-only`; `:network` is an explicit network request that managed `sandbox.forbid_network` refuses; profiles apply with the other clamps and cannot loosen policy. The profile is part of the sidecar `session.state` posture (additive; protocol stays 1). For a bare `:read-only`, `nexus doctor` now says the native worker runs outside any sandbox and only commands are confined; a profile is not a statement that a run is safe (`docs/SANDBOX_PROFILES.md`). (#795 #814 #816)
12. **Audit export refuses a repository whose own Git configuration names a program, and a workspace with a submodule,** instead of hashing it (`binding` becomes `unavailable`; per the review record on #771 and the PR titles of #772 and #776, `docs/AUDIT.md` was not checked for this wording). (#772 #776)
13. **Budget flags.** Objective-wide tool-invocation and cumulative task-time limits exist (`--max-tool-invocations`, `--max-task-minutes`); an objective that exceeds them stops. (#699 #760 #774)
14. **Event triggers (BG-3).** A workspace `.nexus/triggers.json` fires only while its exact bytes are approved with `nexus triggers approve`; nothing fires on upgrade. Triggers run read-only unattended jobs by default and are rate-limited and quarantined; a webhook needs a `secret` and the runner started with `--webhook-port`; the listener binds loopback unless `--webhook-allow-remote` is given and an approved webhook trigger has a secret. The webhook MAC (`X-Nexus-Signature: v1=...`) covers a version tag, the route, the timestamp, the delivery id and the body with its length, so a signature cannot be re-split or replayed on another trigger; delivery ids are restricted and a replayed id is refused. Webhooks are plain HTTP: the MAC protects integrity, not confidentiality. `secretEnv` names must match `NEXUS_TRIGGER_[A-Z0-9_]{1,49}`. Watcher paths that are symlinks leaving the workspace are refused. (`docs/TRIGGERS.md`, #803 #812)

## Security notes and limits

- Nothing in this candidate is independent qualification. The review record (agent-run reviews posted as PR comments, with the defects they found and the follow-ups still open) is in the readiness inventory.
- A command that runs without a sandbox, with your rights, can fake a terminal and approve project hooks, workspace plugins and triggers, or write the approval stores. Run the agent sandboxed, or keep approvals on, for untrusted repositories.
- Any other process of the same user can change approval stores, goal state and runner state. Goal state is not signed.
- Workspace JS plugins run in process after approval (deprecated; subprocess execution is deferred to v1.4); manifest plugins run as subprocesses with the project-hook rules.
- Sandbox: Bubblewrap and Docker only, exercised on one host kernel; no kernel-level or seccomp guarantee is claimed; other kernels and bwrap versions are unmeasured.
- A `--listen` socket and its descriptor are readable by an unsandboxed approved command; `--listen` without `--sandbox` is a documented limit.
- The sweep of a cancelled verification's process tree is bounded: a tree that forks in every pass can leave a child behind (`docs/evidence/v1.3.0/VR2.md`).
- Open issues and follow-ups carried as known limitations: #800 (`startsWith("..")` containment sites; not a gate unless a site shows a bypass), #807 (unattended `prepare` overriding a stale goal pause), the #811 follow-ups (not re-verified), five non-blocking suggestions from the BG-3 re-review (#812), a shared posture helper (#816), and the BG-3, WP-P10-02 and PA-4 items under "Not in this candidate". The list with sources is in the readiness inventory.
- Live inference is the project's gateway only; no gateway measurement for v1.3.0 is recorded.
