# Nexus Code v1.2.2

**Maturity:** the implemented v1.2.2 work is listed below. Remaining work and partial limitations are recorded in [`docs/v1.2.2/BACKLOG.md`](../v1.2.2/BACKLOG.md) and under "Not in this release" and "Known limitations" here. **External qualification is pending.** This is not a claim that Nexus Code is frontier-grade. Every test, scenario and measurement named here is internal validation, and the figures are reported as measured, including the ones that miss. Candidate: [rc.1](v1.2.2-rc.1.md).

## What is in this release

- **Containment.** Operator command rules (`~/.config/nexus/command_rules.json`, never read from a project): a shell command is `allow`ed without a prompt, `prompt`ed even in auto mode, or `forbidden` in every mode, and the deciding rule is recorded in the session export (CS-9, `docs/COMMAND_RULES.md`). With `--sandbox`, the native worker `harness-core` itself runs inside the sandbox, so a bug in it has the limits a command has: Bubblewrap, and on Linux Docker (CS-10). Whenever the worker is sandboxed, file, search, parse and git tools go to a second worker that refuses to run commands and has no network even with `--sandbox-network`. The implementer and tester roles are refused the tools that reach outside the task (VC-8).
- **MCP and plugin tools work.** They were offered to the model but never registered, so every call answered `FAIL-001: Tool ... is not registered` and the server never received `tools/call`. They are now registered as `extension` capabilities after connection.
- **Headless runs end with a question instead of stalling.** A headless run that needs a decision nobody is there to make ends `BLOCKED / NEEDS_INPUT` with a machine-readable question and resumes with `--answer`. This release covers a write, command or egress approval, a verification-file edit, the verifier or type-check at completion, a delegated subagent's question, a requirement the model marks blocked (answered in free text, `--answer <id>=reply:<text>`) and steering that would drop a requirement and went undecided (VC-9).
- **Verification and review.** Operator-authorised regression obligations are replayed by every later attempt and block completion while unmet (VC-2); type-check errors that newly appear in a file the task never touched block completion, for TypeScript, Go, Python and Cargo projects (VC-6), and a type-checker that colours its output (`FORCE_COLOR=1`) is no longer misread as "could not run"; the convergence stop also applies to verifier commands run through `run_tests` (VC-7); `/requirements differential` runs a reference command against the verifier on operator inputs (VC-3); significant independent reviews require eight engineering-assessment fields; a command that fails with only volatile text changing counts as the same failure (CS-11).
- **Context.** Opt-in tool-output masking (`NEXUS_TOOL_OUTPUT_MASK_TOKENS`, CX-4): measured on three large-output tasks, all 30 runs passed and median prompt tokens fell 42 to 61% at 2000; kept opt-in because one model and tasks that all passed cannot show where masking would lose evidence (`docs/evidence/v1.2.2/CX-4-masking-measurement.md`). `@path` imports in project instruction files (CX-7). Opt-in Anthropic prompt-cache hints (CX-6, not validated against the live API).
- **Sessions.** `/fork` and `--fork-session` continue in a copy of a session; a worktree-bound session fork creates a separate checkout and copies staged and unstaged tracked changes plus bounded non-ignored untracked files (RD-6). Saving progress no longer fails because of a worktree binding left over from an earlier turn (found as an intermittent test failure that depended on whether a random-looking workspace directory name tripped the secret classifier).
- **Language servers.** `lsp_diagnostics`, `lsp_hover` and `lsp_definition` never worked for TypeScript, JavaScript or Python (the servers were started without `--stdio` and exited at once); fixed. Rust diagnostics no longer report a file with type errors as clean. A weekly real-server job runs typescript, python, go and rust (CS-6).
- **Operations and CI.** A scheduled gateway conformance job and its claim and alert protocol (MQ-4, `docs/GATEWAY_CONFORMANCE.md`). Median PR CI time is 27 minutes 12 seconds over the first 20 runs after the CLI suite was sharded inside the existing jobs, against 42 minutes 19 seconds before (PC-1, `docs/evidence/v1.2.2/PC-1_POST_SHARDING_2026-11-21.md`). `nexus uninstall` for managed installations (RD-7).
- **Also on this release, from the v1.3.0 track (not part of the v1.2.2 backlog).** `/batch` runs a validated dependency graph of work units on the operation engine, parallel operation work is admitted by resource budget, and delegated children run under an enforced transient authority (`docs/v1.3.0/`). They are in this release because they are on `main`; their status, including "qualification pending" for transient delegation, is the one recorded in those documents.

## Behaviour changes to know about

- In `nexus run`, a requirement the model marks blocked now ends the run `BLOCKED / NEEDS_INPUT` (exit code still 1, task status `failed`) instead of `COMPLETED / REQUIREMENTS_INCOMPLETE`. The REPL, the sidecar and library callers are unchanged.
- On Linux, `--sandbox docker` runs the worker inside the container and refuses to start it outside one. Commands in one session share that container's `/tmp`; before, each command got a fresh container. Elsewhere Docker still confines commands only (`nexus doctor` says which applies).
- Steering that would drop a requirement and got no decision before its turn ended now ends that turn `BLOCKED / NEEDS_INPUT`.
- The implementer and tester roles no longer have the browser tools or `manage_knowledge`; the tester also loses `fetch_web`, `search_web` and `spawn_subagent`.

## Not in this release

Deferred with a dated note in the backlog: the false-completion benchmark and its report (MQ-1, MQ-2; no external measurement is published for this release), macOS and arm64 artifacts (RD-1, RD-2), live validation of the Anthropic and Bedrock cache path (CX-6), the steering semantic judge (VC-10), splitting the two large TUI source files (MT-2), and a default threshold for tool-output masking (CX-4).

## Known limitations

- Nothing here is independent qualification.
- In `verificationPaths.mode=block`, uncertain edits to verification files are refused before side effects. Workspace-controlled test commands can still fabricate their own output, so a passing line is not proof that a test body ran (VC-2).
- Live inference is the project's gateway only. The first scheduled conformance run, on the published v1.2.1 archive, was **not conformant**: `engineering/deep` 200 of 200 native-valid, but `engineering/lead-reasoning` 155 of 200 (77.5%), `edit_file` 5 of 50, the same count as the earlier run on that archive. When observed on 2026-11-20 the gateway's five listed aliases were served by two distinct models (`docs/evidence/v1.2.2/WM-3-gateway-aliases.md`). On 2026-11-21 the operator added a third model on a separate host: the catalog now lists seven aliases, and `engineering/auto` (a 16384-token context) and `engineering/interactive` can each be answered by more than one model. No measurement cited in these notes covers the third model, and which model serves an alias can change. The measurements recorded under `docs/evidence/v1.2.2/` were taken on the named release-candidate or published-v1.2.1 archives; a measurement is only valid for its archive. No stable-v1.2.2 conformance measurement is included here.
- The Docker worker depends on starting the host-built binary through its own loader and libraries inside the container image; it is covered by tests on a Linux host with a Docker daemon and on the hosted runner. A container that fails to start surfaces as a worker disconnect.
- The files-only worker's refusal to run commands is a check inside the process; what holds if that process is compromised is its sandbox (no network, no path outside the workspace). The two workers share the workspace.
- A blocked-requirement or steering-conflict answer lives in the invoking process; a new objective starts a new ledger, so an old conflict can no longer be answered. The Rust TUI shows the blocked turn but has no key for the sidecar `answer` command.
- The CI timing sample is one four-hour window; eight of its 20 executions were failed runs, which finish sooner.
