# Nexus Code v1.0.0-rc.12 release candidate

**Maturity:** release candidate; prerelease, not stable.

**Not published:** the `v1.0.0-rc.12` release workflow failed in its test step, so no RC12 package exists. [RC13](v1.0.0-rc.13.md) replaces it with the same product changes.

**Status:** this candidate is for exact-artifact qualification. It does not establish independent acceptance or authorize stable v1.0.0 promotion. Qualification results must identify the workflow-produced package and its digest.

This release packages the Nexus Code Linux x86-64 client: the TypeScript CLI and sidecar, production Node dependencies, Rust `harness-core`, and Ratatui `nexus-tui`. It supersedes RC11 because a power-loss test found that an interrupted upgrade could leave the installation unable to start. Everything in the [RC11 notes](v1.0.0-rc.11.md) is included.

## Changes since RC11

### Fixes

- **Upgrade durability:** `nexus upgrade` now flushes every file and directory of the extracted package to disk before it moves the package into place and switches the launcher. Previously a power cut after the launcher switch could leave `bin/nexus` at 0 bytes, so neither `nexus` nor `nexus upgrade --recover` could run. Found by a QEMU/KVM power-cut test of RC10; RC11 has the same defect.
- **Installer durability:** `install.sh` now syncs after the verified extraction, before repointing the launcher, and after the switch. Re-running the installer over a working installation had the same 0-byte launcher exposure.

### Qualification tooling (not in the package)

- The evaluator binds the pinned Go and Rust toolchains read-only and masks unpinned compilers that are visible to candidates. CI removes the hosted runner's preinstalled SDK trees before evaluator tests, so the fail-closed compiler inventory stays inside its fixed 25 s deadline.
- RC10 platform evidence wording was narrowed to the outcomes the journal-recovery fixture actually checks.

## Runtime requirements

- Linux x86-64 with glibc 2.35 or newer.
- Node.js 22 or newer.
- An OpenAI-compatible inference endpoint, local or explicitly selected provider.

The archive does not include Node.js. Rust and Cargo are not required at runtime. No other OS or architecture is claimed.
