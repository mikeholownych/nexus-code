# Nexus Code v1.1.2

**Nexus Code v1.1.2** targets the full WP-1101–WP-1108 roadmap that was originally planned for v1.1.0. The v1.1.0 release failed and published no release files; v1.1.1 is the published predecessor. Version numbers are immutable, so the roadmap work is assigned to v1.1.2.

## Release scope and status

The intended scope is the complete [WP-1101–WP-1108 roadmap](../v1.1.0/ROADMAP.md), together with any already-approved corrective changes needed for the candidate. The operation message-delivery correction described below remains relevant context for the v1.1.1 predecessor.

This document records the target scope; it does not claim that the roadmap is implemented or qualified. As of this note, roadmap implementation and v1.1.2 qualification remain incomplete; completion requires recording the applicable evidence. Work-package completion, exact-head test and type gates, independent review, release-candidate qualification, and publication are still required before v1.1.2 can be called released. Track implementation and evidence in the work-package plans and release qualification record.

## Fixed

### A crash-resumed unit no longer receives a multi-message prompt's later messages twice

When a work unit's prompt carried two or more operator or inter-unit messages, and Nexus stopped after submitting that prompt but before the unit's result was saved, resume recognised only the **first** message as already submitted. Every later message from that prompt was injected into the unit's conversation again.

Resume now recognises each message in a submitted prompt's messages block, whatever its position. Matching is still limited to prompts that Nexus issued (`isSubmittedUnitPrompt`, from v1.1.1), so marker text in model output, tool output, or files cannot suppress a message.

- Impact in v1.1.1: the duplicated message was advisory context only. No message was lost, and no `TurnResult`, verification, or acceptance outcome was affected.
- Regression coverage: the post-prompt crash test in `cli/test/operation_release_review.test.ts` now carries two messages. It asserts that each message appears once in the durable history and is acknowledged once.

## Correction to the v1.1.1 notes

The v1.1.1 notes say that a recipient receives undelivered messages "at most once". That holds for prompts carrying a single message. For prompts carrying several messages, v1.1.1 could re-inject the second and later messages after a post-submission crash, as described above. v1.1.2 makes the statement hold in both cases. `docs/releases/v1.1.1.md` carries a matching addendum.

## Runtime requirements

Unchanged from v1.1.1: Linux x86-64 with glibc 2.35 or newer, Node.js 22 or newer, and an OpenAI-compatible inference endpoint (local or an explicitly selected provider). The archive does not include Node.js. Rust and Cargo are not required at runtime.

## Upgrade

Operation records are unchanged: operation schema version 2, as in v1.1.1. No migration runs, and v1.1.1 can read records written by v1.1.2.

Qualification must cover the complete WP-1101–WP-1108 scope on the exact final candidate, including its full test and type gates, package and upgrade checks, independent review, and installed-candidate acceptance. v1.1.1 qualification or evidence from an earlier candidate does not qualify the final v1.1.2 candidate.
