# Nexus Code v1.1.4-rc.2 (release candidate)

**Maturity:** release candidate. The findings ledger is closed except for the items listed under "Not closed"; external qualification is pending. This is **not** a claim that the client is frontier-grade. Supersedes [`v1.1.4-rc.1`](v1.1.4-rc.1.md); everything in rc.1 still applies.

Status of every finding: [`docs/v1.1.4/FINDINGS.md`](../v1.1.4/FINDINGS.md). The exact-head verification record is the CI run on the release PR.

## What changed since rc.1

- **A tool call written as reply text is never run, and the client asks again (#487).** Some reasoning models return a tool call as JSON in the message text with no native `tool_calls`. The client does not execute that text (REQ-AGT-112, VER-02). It tells the model so and asks again; if the reply is call-shaped again it asks once more with `tool_choice: required`. Only a native call from a retry is used, and it goes through the normal approval path. Quoting a call in prose (an explanation that echoes the request's own values) is not treated as a call. The retries are counted in the live matrix as `feedbackRetries` and `forcedRetries`.
- **A rotated credential is re-verified on a 401 retry (#487).** The retried request no longer reuses the server-kind decision made for the old credential.
- **Live-gateway evidence is trustworthy (#484, #485).** The G1.1-4 matrix paces requests, retries 429, sends `Cache-Control: no-cache` to a caching gateway and aborts unless every answered request reports `x-aihost-cache: BYPASS`, so cached replies cannot inflate the count. Gateway `reasoning_content` is counted as hybrid reasoning. Committed evidence: `docs/evidence/v1.1.4/wp-1107-provider-matrix.json`.
- **Confined `.bin` symlinks are accepted in extracted archives (#484)** only when each link resolves to a regular manifested file; nothing is written beneath a link.
- **`cargo clippy -D warnings` passes (#486),** lint-only, behaviour preserving; the rc.1 note listing this as accepted debt is retired.
- **A test no longer rewrites the operator's `config.env` (#484).**

## Not closed

- **G1.1-4 (99.5% valid tool calls on live providers) is NOT MET as measured on rc.1** (ledger WP-1107, I-5): 155/200 and 195/200 native-valid on two reasoning aliases through the owner's gateway. rc.2 adds the re-ask recovery above; it has **not yet been re-measured** and no claim is made until it is. A miss stays recorded as NOT MET.
- **I-6 (grammar smoke on a direct llama.cpp host) is withdrawn on its premise** (this environment's only live inference is the gateway; no such host exists). Agent-recorded; the owner may veto. `toolGrammarDefault` stays `false`.
- **CERI baseline identity and evidence-store verification (audit F02, F06)** are not implemented; CERI comparisons are non-certifying.
- Accepted limitations: ledger sections A4a, J and K (D-04 review lows, auto-repeat detection by timing only). A user who asks the model to print an example call can still end in a forced native call; it goes through normal approval, so auto and full-access modes would run it.
- Known load-sensitive tests, rerun once on failure in CI: as listed in rc.1.
- Owner decisions on the Entire gate and the I-4 dogfood sign-off are unchanged from rc.1.
