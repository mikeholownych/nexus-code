# Nexus Code v1.0.0-rc.1 Release Candidate

**Maturity:** Release Candidate, SemVer prerelease candidate for `v1.0.0`.

**Status:** Candidate for release qualification under `ACCEPTANCE.md`. Built and packaged via `.github/workflows/release.yml` on Ubuntu x86-64 runners; assets verified against `SHA256SUMS`, CycloneDX SBOM (`sbom.cdx.json`), and SLSA provenance.

This is the first Release Candidate for Nexus Code v1.0.0. It marks the feature and architecture freeze for v1.0.0. All source gates, CodeQL security checks, and requirements enforcement have passed. Final promotion to stable `v1.0.0` is gated on post-tag exact-RC qualification (§§4–8).

Install and evaluate this release candidate using:
```bash
curl -fsSL https://raw.githubusercontent.com/mikeholownych/nexus-code/main/install.sh | NEXUS_VERSION=v1.0.0-rc.1 bash
```

## Highlights & Major Changes Since v0.1.0-alpha.2

### 1. Unified Core Architecture & Ratatui Interactive TUI
- **Dual-Engine Core:** High-performance Rust binary (`harness-core`) paired with a modular TypeScript CLI/sidecar architecture.
- **Interactive Terminal UI (`nexus-tui`):** Modern Ratatui-based terminal dashboard providing real-time streaming tokens, process monitoring, turn state inspection, tool execution trees, and keyboard steering.
- **PTY Session Management:** Scripted and interactive PTY lifecycle controls with leak-free teardown and signal propagation (`portable-pty`).

### 2. Strict Token Accounting & Capability Discovery
- **Provider Capability Negotiation:** Dynamic discovery of model context windows, max output token limits, and reasoning capabilities via provider `/models` endpoints (homelab-ai gateway, vLLM, LM Studio).
- **Exact Tokenization:** Native integration with provider tokenizers (`/v1/tokenize`) for byte-accurate token counts prior to dispatch.
- **Enforcement Mode:** `--strict-token-count` rejects unmeasured prompts and prevents mid-turn context truncation.

### 3. Durability, Crash Safety & Compaction
- **Ordered Durable Commits:** Compaction and turn state are committed sequentially with explicit `fsync` barriers (archive, state, session journal). Recovery ignores uncommitted entries without data corruption.
- **Multi-Tenant State Protection:** Isolation guards protect state stores against concurrent lease corruption, race conditions, and unvalidated worktree paths.
- **Crash-Safe Staged Restore:** Atomic restore mechanism with persistent startup recovery markers ensures zero session loss across unexpected host restarts or power cuts.
- **Continuous Execution:** Turns progress across durable segment checkpoints without arbitrary step or time ceilings, stopping deterministically on completion, loop detection, progress failure, or explicit user limits.

### 4. Security Hardening & Zero CodeQL Alerts
- **Clean Security Posture:** 0 CodeQL security alerts repository-wide across JavaScript/TypeScript and Rust.
- **ReDoS Elimination:** Replaced polynomial regular expressions with linear-time whitespace and endpoint scans (`tokens.ts`, `client.ts`).
- **Command & Argument Injection Defense:** Strict argv array parsing and boundaries for notifications, probes, and Docker sandboxes (`isolatedArgv`, `spawnContained`).
- **Sandbox Boundary & Resource Controls:** Bubblewrap unprivileged user namespace sandboxing with cgroup-v2 enforcement (CPU quota throttling, OOM reaping, PID limits, dedicated tmpfs memory caps).
- **Operator Isolation:** Complete isolation of operator home directory (`$HOME`, `~/.nexus`, `~/.config/nexus`) during execution and testing.

### 5. Deterministic Packaging & Supply Chain Assurance
- **Bit-for-Bit Reproducible Packaging:** Hosted `linux-x86_64` runner produces byte-identical packages across independent clean builds (`cmp` verified on `.tar.gz`, `SHA256SUMS`, and third-party notices).
- **CycloneDX SBOM:** Validated automated software bill of materials (`sbom.cdx.json`).
- **Version Synchronization:** Centralized version authority enforced across `package.json`, `cli/package-lock.json`, and `core/Cargo.lock` via `scripts/sync-version.mjs`.

## Known Limits & Qualification Pending

Per `ACCEPTANCE.md` §1.1, the following 11 qualification requirements remain pending post-tag exact-RC qualification and are explicitly deferred in pre-RC `--enforce`:

1. **E2 Platform Matrix (`REQ-QUAL-107`, `ACC-PLAT`):** Qualification across 16 Linux container rootfs environments (Alpine, Debian, Ubuntu, Fedora, Arch, Rocky, openSUSE, etc.).
2. **E3 Terminal Matrix (`REQ-QUAL-108`, `ACC-TUI-MANUAL`):** Human verification across 5 terminal environments × 3 window dimensions.
3. **E4 Standalone Inference (`REQ-PRV-003`, `REQ-QUAL-107`, `ACC-PRV-STANDALONE`):** Direct inference validation against standalone vLLM / LM Studio endpoints without gateway.
4. **E5 Cloud Providers (`REQ-PRV-111`, `ACC-PRV-LIVE`):** Live smoke checks across configured cloud providers.
5. **T2 / T3 / T4 Evaluations under `GATEWAY` (`REQ-AGT-002`, `REQ-QUAL-101`, `REQ-QUAL-109`):**
   - **T2 Held-Out Tasks:** Sealed 40-task benchmark evaluated with zero implementer access.
   - **T3 Long-Task Multi-Turn:** 8 complex scenarios × 5 repetitions with kill/resume durability testing.
   - **T4 Fault Injection:** 9 error classes × 5 repetitions validating loop detection, tool recovery, and process reap.
6. **Supply Chain & Cross-Runner Reproducibility (`REQ-REL-005`, `REQ-REL-114`, `ACC-SUP-08`):** Verification across Ubuntu 22.04 and Ubuntu 24.04 runners.
7. **Trust & Governance (`REQ-AGT-010`, `REQ-AGT-110`, `ACC-TRUST-04`, `ACC-GOV-06`):** Final signed G6 disposition by independent reviewer.

## Runtime Requirements

- **Operating System:** Linux x86-64 with glibc 2.35 or newer (Ubuntu 22.04+, Debian 12+, Fedora 38+, Arch Linux).
- **Node.js:** Node.js 20.x, 22.x, or 24.x.
- **Inference Server:** Local or networked OpenAI-compatible endpoint (vLLM, LM Studio, Ollama, homelab-ai gateway) or supported cloud API.
- **Kernel Controls (Optional for full sandboxing):** Unprivileged user namespaces (`bubblewrap`) and cgroups v2 for resource containment.

Rust and Cargo are build-time requirements only; runtime binary artifacts (`harness-core`, `nexus-tui`) are self-contained.
