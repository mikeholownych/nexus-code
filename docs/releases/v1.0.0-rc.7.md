# Nexus Code v1.0.0-rc.7 release candidate

**Maturity:** release candidate; prerelease, not stable.

**Status:** this candidate is for exact-artifact qualification. It does not establish independent acceptance or authorize stable v1.0.0 promotion. Qualification results must identify the workflow-produced package and its digest.

This release packages the Nexus Code Linux x86-64 client: the TypeScript CLI and sidecar, production Node dependencies, Rust `harness-core`, and Ratatui `nexus-tui`.

## Changes since RC6

- The installer now attempts build-provenance verification automatically when a trusted GitHub CLI is available and reports when verification is skipped. Set `NEXUS_VERIFY_ATTESTATION=1` to require verification or `=0` to skip it. `nexus upgrade` reports the verification outcome as well.
- Checkpoint verification failures in both the TUI and REPL return actionable recovery choices. Retrying is separate from consent to persist sensitive state, and recovery does not bypass protected Git validation.
- Terminal sanitization now covers streamed assistant output and the task prompt, in addition to turn summaries and inference-origin status messages. This does not sanitize every diagnostic or status output.

## Runtime requirements

- Linux x86-64 with glibc 2.35 or newer.
- Node.js 22 or newer.
- An OpenAI-compatible inference endpoint, local or explicitly selected provider.

The archive does not include Node.js. Rust and Cargo are not required at runtime. No other OS or architecture is claimed.

## Candidate assets

The release workflow for `v1.0.0-rc.7` is expected to produce the version-matched Linux archive, `SHA256SUMS`, SBOM, notices, installer, and provenance. The workflow run, tag commit, artifact digests, and qualification evidence must be recorded before this candidate can be accepted. Local builds are not interchangeable with the workflow-produced artifacts.
