# Nexus Code v1.0.0-rc.4 release candidate

**Maturity:** release candidate; prerelease, not stable.

**Status:** this candidate is for exact-artifact qualification. It does not establish independent acceptance or authorize stable v1.0.0 promotion. Qualification results must identify the workflow-produced package and its digest.

This release packages the Nexus Code Linux x86-64 client: the TypeScript CLI and sidecar, production Node dependencies, Rust `harness-core`, and Ratatui `nexus-tui`.

## Changes since RC3

- Updates Tokio to 1.53.3 to address the unsound safe `AsyncFd` constructors reported in RUSTSEC-2026-0386.
- Classifies length-truncated assistant output separately from recoverable provider failures, so truncated tool arguments are not retried through provider recovery.
- Strips terminal control characters from decoded HTML and web-search text before displaying untrusted results.
- Normalizes slash and backslash separators before checking archive symlink targets, rejecting targets whose normalized destination escapes the package root.
- Tightens `--read-only` shell commands: operands are checked through resolved paths (symlinks, content-reading globs, `--` and option clusters for `grep`/`rg`/`diff`), and commands run only inside Bubblewrap with no network, a cleared environment, a private PID namespace, a minimal read-only runtime, and the workspace bound through a descriptor pinned when the session starts. On hosts without a usable Bubblewrap, including Docker-only hosts, read-only shell commands are now refused instead of running unconfined.
- Keeps `safeFetch` running when a pinned address is unreachable, and repairs tool calls that mix single- and double-quoted strings without rewriting single-quoted contents.
- Makes the evaluator fail closed when a candidate's identity cannot be resolved. Candidate identity now hashes untracked directory trees and nested worktree files recursively, skips `.git` metadata, walks directories by descriptor without following symlinks, and refuses unsupported file types or traversals beyond its depth, entry and byte bounds instead of reporting a partial identity.
- Confines checkpoint handling: checkpoint records are validated and bound to their filenames, their fields are never interpolated into shell commands, and checkpoint restore, prune and retention only delete or copy snapshot directories inside the checkpoint store.
- Recognizes `.nexus` in `.git/info/exclude` only as a whole ignore rule, so comments or similarly named patterns no longer leave Nexus state trackable by git.
- Makes `nexus doctor` warn when the session or task store exists but cannot be read, instead of reporting it as empty.
- Unregisters background services that exit during startup, so they are not left registered as running.
- Locks the npm release tools used for notices and the SBOM, rejects deprecated packages in that lock, and adds a cross-runner workflow that rebuilds a published RC on Ubuntu 22.04 and 24.04 and compares the archive, compatibility metadata, checksums, notices, SBOM and installer with the published assets.
- Requires the approved digest-pinned Rust builder for release packaging and reproducibility checks. Local packaging examples and cross-runner checks use the same approved builder identity; the host-build opt-out is for local development only.

These source changes and their CI results do not replace RC4 artifact checks or installed-package qualification.

## Runtime requirements

- Linux x86-64 with glibc 2.35 or newer.
- Node.js 22 or newer.
- An OpenAI-compatible inference endpoint, local or explicitly selected provider.

The archive does not include Node.js. Rust and Cargo are not required at runtime. No other OS or architecture is claimed.

## Candidate assets

The release workflow for `v1.0.0-rc.4` is expected to produce the version-matched Linux archive, `SHA256SUMS`, SBOM, notices, installer, and provenance. The workflow run, tag commit, artifact digests, and qualification evidence must be recorded before this candidate can be accepted. Local builds are not interchangeable with the workflow-produced artifacts.
