# Nexus Code v1.0.0 Release Notes & Migration Guide

**Maturity:** Stable release (v1.0.0).

This release delivers the complete Nexus Code client architecture with comprehensive boundary hardening, process ownership, workspace trust enforcement, and egress protection.

---

## 1. Security & Untrusted Input Boundary Hardening (PLAN-03)

### Workspace `.env` Isolation & Allowlist (REQ-SEC-110)
- **Problem addressed (PRV-01):** Workspace `.env` files previously loaded with `override: true`, allowing untrusted repositories to manipulate `NODE_TLS_REJECT_UNAUTHORIZED`, proxy configurations, credential variables, timeouts, and fallback endpoints.
- **New behavior:** Project `.env` files are parsed into an isolated `EffectiveConfig` layer and are **never** assigned to `process.env`.
- **Allowed project keys:**
  - `LOCAL_LLM_ENDPOINT`
  - `LOCAL_LLM_MODEL`
  - `LOCAL_LLM_TASK_CLASS`
  - `NEXUS_CONTEXT_LIMIT`
  - Any key starting with the documented prefix `NEXUS_PROJECT_*`
- **Ignored project keys:** All other environment keys—including `NODE_*`, `*_PROXY`, `HOME`, `PATH`, `SSL_*`, provider credentials (`OPENAI_API_KEY`, etc.), `LOCAL_LLM_API_KEY`, `LOCAL_LLM_TIMEOUT_MS`, and `LOCAL_LLM_FALLBACK_ENDPOINTS`—are ignored with startup notices and flagged in `nexus doctor`.
- **Escape hatch:** For transition during pre-1.0 release evaluation, `NEXUS_LEGACY_PROJECT_ENV=1` is supported as a temporary operator override.

### Migration Guide for Project `.env` Keys

If your project `.env` contains settings that are now ignored, migrate them to your operator configuration:

| Setting in project `.env` | Where to move it |
| :--- | :--- |
| Provider API keys (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, etc.) | `~/.config/nexus/config.env` or shell environment |
| Appliance API key (`LOCAL_LLM_API_KEY`) | `~/.config/nexus/config.env` |
| Proxy settings (`HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY`) | Shell profile or `~/.config/nexus/config.env` |
| Custom CA certs (`NODE_EXTRA_CA_CERTS`, `SSL_CERT_FILE`) | Shell profile or `~/.config/nexus/config.env` |
| TLS settings (`NODE_TLS_REJECT_UNAUTHORIZED`) | Operator shell environment (caution: disables certificate validation) |
| Local LLM timeouts (`LOCAL_LLM_TIMEOUT_MS`) | `~/.config/nexus/config.env` |
| Fallback endpoints (`LOCAL_LLM_FALLBACK_ENDPOINTS`) | `~/.config/nexus/config.env` or CLI `--fallback` |

To inspect which keys in your current workspace are ignored, run:
```bash
nexus doctor
```

### Destination Locality Classification (REQ-SEC-111)
- Locality is derived from parsed IP literals and CIDRs (loopback `127/8`, `::1`; RFC-1918 `10/8`, `172.16/12`, `192.168/16`; CGNAT `100.64/10`; link-local; IPv6 ULA `fc00::/7`).
- Hostnames are treated as external destinations by default unless the host is `localhost`, matches the operator-configured local endpoint, or is explicitly declared in `NEXUS_LOCAL_ORIGINS`.
- DNS resolution is explicitly never used to grant locality (preventing DNS rebinding bypasses).
- Operators running local LAN or Tailscale inference servers can declare them local via:
  ```bash
  # in ~/.config/nexus/config.env or shell environment:
  NEXUS_LOCAL_ORIGINS="gpubox:8000,lan-llm.home"
  ```

### SSRF-Safe Outbound Fetching (REQ-SEC-112)
- `fetch_web` enforces `safeFetch`: DNS resolution pinning, manual redirect handling up to 5 hops (with per-hop IP validation against private/loopback/CGNAT/link-local/ULA CIDRs), and a streaming response body cap of 5 MB.

### Workspace Trust: Skills & Knowledge (REQ-SEC-113, REQ-SEC-114)
- Workspace trust now gates workspace skill directories (`skills/`, `.nexus/skills/`, `.claude/skills/`) and workspace knowledge (`.nexus/knowledge.json`).
- In untrusted workspaces, workspace skills are listed by `/skills` as "untrusted (not loaded)" and cannot be activated via `/skill <name>` or `activate_skill`. Run `nexus trust .` to trust the workspace.
- Injected system prompt blocks from skills and knowledge include explicit provenance metadata: `[source: <path>] [trust: <state>]` (CTX-001).
- Automatic knowledge extraction (`autoExtract`) is disabled by default (DEC-15). It can be enabled with `NEXUS_KNOWLEDGE_AUTOEXTRACT=1`, which issues a notification when new rules are persisted.
- `--read-only` mode never creates `.nexus/` or writes knowledge files.

### Plugin Architecture & EXT-004 Auditing (REQ-SEC-115, REQ-SEC-116, REQ-SEC-117)
- Plugins execute in-process with full user authority. The legacy worker-thread sandbox claim has been removed, and `executeSandboxed` deleted.
- The undocumented foreign plugin directory `~/.config/opencode/plugins` has been removed. Plugins are only loaded from `~/.config/nexus/plugins/`, `~/.nexus/plugins/`, and trusted workspace directories.
- Any plugin middleware rewrite of tool arguments or results is cryptographically recorded with before and after SHA-256 digests in both `~/.nexus/audit.log` and the session flight log (EXT-004).

### Protected Path Hardening (REQ-SEC-118)
- File protection rules now match `.env*` prefixes (e.g. `.env`, `.env.local`, `.env.production`), `id_rsa*`, and `id_ed25519*` case-insensitively across path components and canonical targets resolving symlinks.
- Protection is enforced across all file read, write, and edit tools (`read_file`, `batch_read`, `edit_file`, `patch_file`, `write_file`, etc.). Path protection remains advisory for `run_command`.

### Web Search Honesty (REQ-PRV-108)
- `search_web` returns `success: false` and empty results when no search hits are found (no fabricated results). Its search destination is disclosed on first use and gated by egress disclosure.
