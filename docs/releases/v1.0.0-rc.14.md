# Nexus Code v1.0.0-rc.14 release candidate

**Maturity:** release candidate; prerelease, not stable.

**Status:** this candidate is for exact-artifact qualification. It does not establish independent acceptance or authorize stable v1.0.0 promotion. Qualification results must identify the workflow-produced package and its digest.

This release packages the Nexus Code Linux x86-64 client: the TypeScript CLI and sidecar, production Node dependencies, Rust `harness-core`, and Ratatui `nexus-tui`. It replaces RC12 and RC13, which were tagged but never published: both release workflows failed in the test step, so neither package exists. RC14 ships the same product changes as RC12; everything in the [RC13](v1.0.0-rc.13.md), [RC12](v1.0.0-rc.12.md) and [RC11](v1.0.0-rc.11.md) notes is included.

## Changes since RC13

### Qualification tooling and release workflow (not in the package)

- The evaluator's compiler-exposure check no longer depends on deleting the hosted runner's preinstalled SDK trees. It masks host-only SDK directories inside the candidate sandbox under every mounted spelling, ignores an inventoried path only when it has been removed before inspection, and reports which part of the check failed. Every other inspection error still refuses qualification. RC13's release run failed when this check refused in two evaluator tests.
- The CLI test step in the release and CI workflows now has a 45-minute limit. RC13's release run and a main CI run stalled after the evaluator test file finished, because its test process did not exit; a hung step now fails the job instead of running for six hours.

No product code changed between RC12's tag and RC14.

## Runtime requirements

- Linux x86-64 with glibc 2.35 or newer.
- Node.js 22 or newer.
- An OpenAI-compatible inference endpoint, local or explicitly selected provider.

The archive does not include Node.js. Rust and Cargo are not required at runtime. No other OS or architecture is claimed.

## Candidate assets

The release workflow for `v1.0.0-rc.14` is expected to produce the version-matched Linux archive, `SHA256SUMS`, SBOM, notices, installer, and provenance. The workflow run, tag commit, artifact digests, and qualification evidence must be recorded before this candidate can be accepted. Local builds are not interchangeable with the workflow-produced artifacts.

## Qualification status

This is a candidate, not an accepted release. The installed-RC gates — platform and lifecycle evidence including the power-loss cell, mandatory automated CI PTY (§5.1) and scripted installed-RC PTY (§5.2), provider and standalone qualification, held-out task quality, cross-runner reproducibility, independent exact-RC acceptance and the requirements ledger — remain outstanding for this artifact. RC11 evidence does not carry over to RC14 without an explicit, reviewed carry-forward. The manual matrix (§5.3) is waived for v1.0.0 by DEC-20; this does not waive steering, accessibility, or any other release gate. Passing source CI does not satisfy installed-RC qualification.
