# Nexus Code v1.2.1

**Maturity:** the v1.2.1 plan ([`docs/v1.2.1/PLAN.md`](../v1.2.1/PLAN.md)) is landed except for the units listed under "Not in this release". **External qualification is pending.** This is not a claim that Nexus Code is frontier-grade. Every test, scenario and measurement named here is internal validation, and the figures are reported as measured, including the ones that miss. Candidate: [rc.2](v1.2.1-rc.2.md) (rc.1 was superseded: its release workflow failed on a test fixture and published no archive).

## What is in this release

- **More providers, as data and as native protocols.** Operators declare providers in `~/.config/nexus/providers.json` (validated: https only unless local, no credentials in URLs, header names and templates checked; the file is read from the operator's home, never from a project). A shipped catalog adds the OpenAI-compatible long tail. New native protocols: Gemini (`gemini-generate-content`), Amazon Bedrock Converse (`bedrock-converse`, SigV4 written on `node:crypto`, AWS event-stream framing, credentials from the environment and shared files), and Google Vertex over the Gemini protocol (`gcp-adc`: service-account JWT or `gcloud` token). **The new protocols were verified against fixtures and local mock servers; no live Gemini, Bedrock or Vertex call was made.**
- **Behaviour follows the model's listed capabilities.** `nexus models refresh` (the only command that contacts models.dev) validates and caches model data; context and output limits, tool-choice support and reasoning effort levels come from it and are never assumed when absent. Per-provider spending limits (`NEXUS_CLOUD_LIMITS`) price a provider that reports no cost from the snapshot, and refuse a cost limit that cannot be enforced.
- **Security.** Commands no longer inherit the process's credentials; `--sandbox` confines (HOME masked, no network unless asked); compaction summaries are labelled as untrusted data and checked against the gating requirements; the egress inspector refuses a network call that carries a workspace `.env` secret (its policy comes only from your environment, `NEXUS_EGRESS_POLICY`, never from a repository file; commands behind `env`, `sudo`, `timeout`, `sh -c` and similar are inspected); a prompt-injection scanner labels and fences suspicious tool results and, while you are present, asks before the next step's state-changing calls. **The scanner is a heuristic, not a guarantee.** On its labelled corpus it caught 54 of 64 attacks it was tuned on, 15 of 30 written after it was frozen and 0 of 12 deliberate evasions, and flagged 5 of 45 and 2 of 24 benign samples. `nexus doctor` reports the effective containment (containment stays opt-in).
- **Verification and review.** Operator-declared boundary rules enforced in the review gate; verification-file shell writes can be stopped (`verificationPaths.mode: "block"`); a repeated-call detector with a CERI scenario that fails when it is disabled; each compaction leaves an auditable record checked on resume; `verified` is re-checked on resume; the CERI evidence store checks resolved paths and run ids, and a baseline comparison binds model, sampling, fixture and evaluator identity before it can confirm a regression. The CERI library has no shipped command that reads it yet.
- **Operations.** `nexus run --output stream-json` streams NDJSON events; a composite GitHub Action runs `nexus run --json` with a verification-gated exit code; `examples/` are tested; a weekly flake report records CI rerun events; a nightly real-project smoke job runs the headless CLI against synthetic representative repositories (a populated `node_modules`, a large Makefile reference graph, a deep tree, a pytest project) on a scripted mock gateway and goes red when a repository ends as anything but VERIFIED or REGRESSION_FREE (no live model and no third-party code; the workflow itself has not yet run on a hosted runner).
- **Maintainability.** `cli/src/agent.ts` is split along its seams (8,441 to 4,616 lines) with no test edited; the full suite's failing set is identical before and after.

## Behaviour changes to know about

- The egress inspector blocks a network command that carries a workspace secret by default (`NEXUS_EGRESS_POLICY` to relax it, in your own environment only).
- A tool result the injection scanner flags reaches the model fenced and labelled; the next step's state-changing calls ask you first (interactive only; headless and `--yes` get the label and fence only).
- A cost limit for a provider with no reported cost and no snapshot price is refused as unenforceable, as before; a malformed `NEXUS_CLOUD_LIMITS` refuses every cloud request.

## Not in this release

Deferred with a dated note in the plan: the Terminal-Bench/Harbor adapter and the false-completion report (MQ-1, MQ-2; no external measurement is published for this release), the scheduled gateway-conformance job (MQ-4; the gateway is not reachable from hosted runners), the macOS and arm64 artifacts (RD-1, RD-2), CI wall-time reduction to a measured median under 40 minutes (PC-1; PR runs took about 37 to 45 minutes), collapsing the redaction and terminal-safe variants (MT-3, part done), CERI slices D to G, per-command approval rules, RPC worker isolation, and the P2 units the plan lists as rolling.

## Known limitations

- Nothing here is independent qualification.
- The injection scanner reads English phrasing and misses paraphrases, other languages, look-alike letters and text split by punctuation; see the User Manual for the measured rates.
- The egress inspector cannot see a secret a command builds at run time, one split across arguments, or one transformed beyond URL or base64 encoding.
- A revoked Vertex token keeps failing until it expires (no forced refresh after a 401); Vertex supports service-account key files and `gcloud` only.
- Live inference is the project's gateway only. The G1.1-4 tool-call validity measurement for this release is recorded in `docs/evidence/v1.2.1/` for the release candidate it was taken on; a measurement is valid only for its archive. The previous release did not meet the bar (`engineering/lead-reasoning` 155 of 200 on the published v1.2.0 archive).
