# Nexus Code v1.0.0-rc.6 release candidate

**Maturity:** release candidate; prerelease, not stable.

**Status:** this candidate is for exact-artifact qualification. It does not establish independent acceptance or authorize stable v1.0.0 promotion. Qualification results must identify the workflow-produced package and its digest.

This release packages the Nexus Code Linux x86-64 client: the TypeScript CLI and sidecar, production Node dependencies, Rust `harness-core`, and Ratatui `nexus-tui`.

## Changes since RC5

- Pins the release package builder and cross-runner rebuilds to Node.js 22.22.1 and npm 10.9.4. This keeps generated SBOM tool metadata identical across both reproducibility runners and the published candidate.
- Escapes untrusted text in turn summaries and inference-origin status lines before rendering; regression tests cover those fields. Streaming assistant-token output and echoed task prompts remain unsanitized and are known limitations.
- The installer verifies build provenance when possible again. `NEXUS_VERIFY_ATTESTATION` defaults to `auto`: with a GitHub CLI at `/usr/bin/gh` or `/usr/local/bin/gh` it verifies the archive and `SHA256SUMS` attestations, and otherwise it installs after the SHA-256 check with a notice that provenance was not verified. This reverses RC5, whose installer refused to run without a trusted, signed-in GitHub CLI. Set `NEXUS_VERIFY_ATTESTATION=1` to require provenance, or `0` to skip it; any other value, including an empty one, is rejected. `nexus upgrade` follows the same setting and now states in its completion notice when provenance was not verified. A value set in the shell takes precedence over `~/.config/nexus/config.env`.

## Runtime requirements

- Linux x86-64 with glibc 2.35 or newer.
- Node.js 22 or newer.
- An OpenAI-compatible inference endpoint, local or explicitly selected provider.

The archive does not include Node.js. Rust and Cargo are not required at runtime. No other OS or architecture is claimed.

## Candidate assets

The release workflow for `v1.0.0-rc.6` is expected to produce the version-matched Linux archive, `SHA256SUMS`, SBOM, notices, installer, and provenance. The workflow run, tag commit, artifact digests, and qualification evidence must be recorded before this candidate can be accepted. Local builds are not interchangeable with the workflow-produced artifacts.
