# Nexus Code v1.1.4-rc.1 (release candidate)

**Maturity:** release candidate. The findings ledger is closed except for the items listed under "Not closed"; external qualification is pending. This is **not** a claim that the client is frontier-grade: the readiness audit of 2026-11-06 stands, and the measurements it asks for (G1.1-4 on live providers) have not been taken.

Status of every finding: [`docs/v1.1.4/FINDINGS.md`](../v1.1.4/FINDINGS.md). TUI defects: [`docs/v1.1.4/TUI-AUDIT-STATUS.md`](../v1.1.4/TUI-AUDIT-STATUS.md). The exact-head verification record is the CI run on the release PR.

## What is in this release

- **TUI approval safety and polish (WP-1317).** A held or queued key can no longer approve an action (D-01); the remaining 26 audited defects D-02 to D-27 are fixed, each with a regression test and, for the visible ones, a capture under `docs/evidence/v1.1.4/tui/`. Provider wait, first-run and unreachable-endpoint states are shown plainly (D-06, D-07), a stalled stream is reported (D-08), input and scrolling work as the help says (D-09, D-10), `/resume` and `/model` act on this session's workspace and endpoint (D-11, D-15), the trust prompt, exit breadcrumb, orientation card and model panel are sized to their content (D-21 to D-23, D-26), a short paste shows its first line (D-25), and the REPL, TUI and sidecar report the same six state fields (I-3).
- **Verification honesty (D-04).** A turn that ran commands without changing the workspace is no longer reported `UNVERIFIED`; one that changed it, or may have, still is.
- **Evaluator isolation (WP-1105 / A9).** cgroup memory, pid and disk limits for evaluator commands, verified on one cgroup-v2 host, including the case where a command is stopped by the process limit (the operator now sees "candidate command hit the process limit").
- **Worktrunk (WP-1310 to WP-1312)**: named worktrees, merge and prune with a receipt gate, build-cache sharing, `run --worktree`.
- **Parsing, sessions, doctor, config (WP-1303, WP-1304, WP-1306, WP-1308)**: legacy text-mode tool calls counted, partial-session saves keep recovery fields, doctor validates schema-2 message journals off the event loop, `config.env` cannot re-home state, option precedence before a subcommand, relevance-based skill injection, redaction of percent-encoded and dotted key material.

- **Review and evaluation truthfulness (external audit F01 to F07).** A review that lists an unproven criterion can no longer be accepted (F04, on the live review path). In the CERI evaluation library (not used by any shipped command) a run that is not finished or has no assertions can no longer PASS, reports count scheduled, executed and compared runs separately and say "insufficient evidence" without a comparison, malformed evaluation definitions are refused, and efficiency is only compared across identical task populations.

## Not closed

- **G1.1-4 (99.5% valid tool calls on live providers) is not measured** (ledger WP-1107, I-5). The grammar path is verified against mocks and a structural recognizer only; `toolGrammarDefault` stays `false` until the live GBNF smoke passes on the owner's llama.cpp host (I-6).
- **CERI baseline identity and evidence-store verification (audit F02, F06)** are not implemented: CERI comparisons stay non-certifying and are not qualification evidence. The audit's larger build slices are post-release work (ledger section L).
- **Owner dogfood (I-4):** signed off by the owner on 2026-11-13 on the installed `1.1.4-rc.1 (072b8bfd7622)` (the merge of #483); the terminals used were not named.
- **A9 limits:** verified on one host, not on a hosted CI runner; the resource contract is opt-in (`config.resources`).
- Accepted limitations are listed in the ledger sections A4a, J and K (D-04 review lows, the `cargo clippy -D warnings` debt in files this release does not touch, auto-repeat detection by timing only).
- Known load-sensitive tests, rerun once on failure in CI: Rust `runner::tests::cancel_ends_the_command_group`, `code_evaluators_overlay` "a large node_modules/", PTY `tui_approval_input_e2e` "that text is kept in the draft".

## Owner decision: Entire review gate

On 2026-11-12 Entire (the automated review service) was out of credits and the owner decided not to buy more ("Waive Entire, record it"). PR #481 and PR #482 therefore merged **without** a finished Entire Findings gate. In its place: independent reviewer ACCEPTs on each branch head (G1 to G4, A9, #481 round 2), green required CI at the merged head (`test-matrix (22)`, `test-matrix (24)`, `linux-x86_64`), and the integrator's own diff check of every integration fix. This is a recorded waiver, not an Entire pass.

On 2026-11-13 the owner extended this: the Entire gate is no longer a valid gate for any PR, including the release PR. The same substitutes apply.
