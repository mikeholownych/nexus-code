# Nexus Code v1.1.4

**Maturity:** the v1.1.4 findings ledger is closed except for the limitations listed below. **External qualification is pending.** This is not a claim that Nexus Code is frontier-grade; the readiness audit of 2026-11-06 stands, and the measurements here are internal.

Status of every finding: [`docs/v1.1.4/FINDINGS.md`](../v1.1.4/FINDINGS.md). TUI defects: [`docs/v1.1.4/TUI-AUDIT-STATUS.md`](../v1.1.4/TUI-AUDIT-STATUS.md). Candidate histories: [rc.1](v1.1.4-rc.1.md), [rc.2](v1.1.4-rc.2.md), [rc.3](v1.1.4-rc.3.md).

## What is in this release

- **TUI approval safety and polish (WP-1317).** A held or queued key can no longer approve an action; the 27 audited TUI defects are fixed, each with a regression test. Provider wait, first-run, unreachable-endpoint and stalled-stream states are shown plainly; `/resume` and `/model` act on this session's workspace and endpoint; the REPL, TUI and sidecar report the same six state fields.
- **A tool call written as reply text is never run, and the client asks again.** Some reasoning models return a tool call as JSON in the message text with no native `tool_calls`. The client does not execute that text (REQ-AGT-112, VER-02). It tells the model so and asks again; if the reply is call-shaped again it asks once more with `tool_choice: required`. Only a native call from a retry counts, and it goes through the normal approval path.
- **Measured tool-call validity (G1.1-4).** On the rc.2 build, through the project's gateway, with the gateway response cache bypassed: `engineering/deep` 200/200 and `engineering/lead-reasoning` 200/200 native valid calls, zero schema-invalid, zero invalid (45 and 5 attempts needed a re-ask). On rc.1 the same aliases scored 155/200 and 195/200. This is an internal measurement of two gateway aliases on one fixture; it says nothing about other providers. Evidence: `docs/evidence/v1.1.4/wp-1107-provider-matrix.rc.2.json`.
- **Verification honesty.** A turn that ran commands without changing the workspace is no longer reported `UNVERIFIED`; a review that lists an unproven criterion can no longer be accepted.
- **Evaluator isolation (A9).** cgroup memory, pid and disk limits for evaluator commands, verified on one cgroup-v2 host.
- **Worktrunk.** Named worktrees, merge and prune with a receipt gate, build-cache sharing, `run --worktree`.
- **Parsing, sessions, doctor, config.** Legacy text-mode tool calls counted, partial-session saves keep recovery fields, doctor validates schema-2 message journals, `config.env` cannot re-home state, option precedence before a subcommand, redaction of percent-encoded and dotted key material.
- **Live-gateway evidence is trustworthy.** The G1.1-4 matrix paces requests, retries 429 and refuses a run whose responses were not cache-bypassed.
- **`cargo clippy -D warnings` passes** on the core crate (lint-only, behaviour preserving).

## Known limitations

- CERI baseline identity and evidence-store verification (audit F02, F06) are not implemented; CERI comparisons are non-certifying and are not qualification evidence.
- Accepted limitations recorded in the ledger (sections A4a, J, K): D-04 review lows, auto-repeat detection by timing only. A user who asks the model to print an example call can still end in a forced native call; it goes through normal approval, so auto and full-access modes would run it.
- A9 was verified on one host, not on a hosted CI runner; the resource contract is opt-in (`config.resources`).
- I-6 (a grammar smoke on a direct llama.cpp host) was withdrawn on its premise: this project's live inference is the gateway only. `toolGrammarDefault` stays `false`.
- Known load-sensitive tests are rerun once on failure in CI (Rust `runner::tests::cancel_ends_the_command_group`, `code_evaluators_overlay` "a large node_modules/", PTY `tui_approval_input_e2e` "that text is kept in the draft").

## Owner decisions on record

The Entire review gate is no longer a gate for any PR (2026-11-13); in its place each merge needs green required CI, independent local Code, Security and Slop reviews, and the integrator's diff check. The owner signed off the I-4 dogfood on 2026-11-13 on the installed `1.1.4-rc.1 (072b8bfd7622)`.
