## What the five failures are

All five are `edit_file` attempts (45/50) at the same positions in runs 2 and 3: the five "hybrid" prompts that end "Think before the call and emit a non-empty `<think>...</think>` block." Each ended as a 120 s client first-byte timeout (`failureKind: timeout` in the receipts). The other tools, and the non-hybrid `edit_file` prompts, were all valid.

Diagnostics on the same alias, under the GATEWAY claim:

- The plain `edit_file` prompt: 8/8 native valid, about 12.6 s each.
- Five hybrid `edit_file` prompts followed by plain ones, client timeout raised to 200 s: the five hybrid calls each ended `finish_reason=length` ("Model output was truncated; refusing to treat it as a complete answer"), the plain ones were native valid.
- The hybrid prompt sent directly with `tool_choice: "required"` and with `"auto"`: HTTP 200 after about 141 s, `finish_reason=length`, 8192 completion tokens, about 27,000 characters of reasoning, no tool call, in all 6 calls observed (3 each). Forcing the tool call does not change it.

So the model behind `engineering/lead-reasoning` reasons to the output cap on this prompt without calling the tool. The client correctly refuses to treat a truncated reply as an answer.

## Why this is recorded as a limitation and not as a client defect

- The same prompt class failed on the earlier `v1.1.4` run (`wp-1107-provider-matrix.json`: `lead-reasoning` 195/200, with `write_file` hybrid 0/5), and `v1.1.4-rc.2` then passed 200/200 (five forced retries) with the same client code. The outcome moves with the model's behaviour on that prompt, not with the client.
- It was not fixed by changing the matrix, the prompts, the timeouts or the pass bar, and no workaround for this gateway's model was added to the product (the gateway is outside the product's control).
- It is **not** claimed that the 99.5% bar is met for this build. A passing rerun of rc.1 would supersede run 3; none was obtained.

## Follow-up

- This record closes v1.2.1 unit MQ-0 (the rc.1 measurement) with the gate unmet. Whether the client should do anything about a reasoning-capable model that runs to the output cap on a "think first" prompt (for example a per-request reasoning budget) is an open product question, not settled here and not yet a unit.
