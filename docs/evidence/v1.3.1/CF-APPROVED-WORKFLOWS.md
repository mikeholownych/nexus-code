## Operator workflow

1. Run `/batch plan <objective>` and inspect the recorded operator objective and normalized draft with `/batch plan show <draft-id>`. Use the displayed digest for approval. Resolve any outstanding blockers or blocking reviewer findings by creating a revised draft.
2. Authorize reviewed check commands with `--authoritative-verifier` or the operator-only `NEXUS_BATCH_VERIFIER_COMMANDS` JSON array. Each reviewed command must match one of those entries exactly. Each check can declare its own contained working directory, timeout, and requirement. Conditional checks use repository-relative changed-path prefixes. Every plan still includes an unconditional required final check.
3. Start from the clean pinned Git base in the trusted repository root, then run `/batch plan accept <draft-id> <digest> [review-digest]`. Supply the displayed review digest if a review exists. If a temporary import file was used, remove it before admission if it is untracked. The accepted record stores the graph, review, base, and stable operation ID. A plan that declares an execution budget and per-unit reservations may start independent units concurrently in separate worktrees. Repeat approval returns the matching operation once it exists. Use `/batch status <operation-id>`, `/batch results <operation-id>`, and `/batch resume <operation-id>` for lifecycle control.
4. Use `/knowledge suggest operation:<id>` to propose knowledge from a saved terminal operation in the same workspace. Unit summaries carry model provenance. Extraction uses a qualified, context-fitting local resource first. Cloud fallback requires an explicitly authorized origin and is recorded on the suggestion. Passing check records qualify as verified evidence when the check definition, complete execution receipt, and current isolated candidate agree. `/knowledge audit operation:<id>` exposes provenance and decision metadata while keeping suggestion text in private state. Use `/knowledge show-source <ref>` to inspect the protected source projection, including committed archived messages with matching compaction digests.

A waiver records the actor, reason, candidate and check identity, and remains distinguishable from a passing result. A changed candidate, missing result, timeout, truncation, or cancellation cannot use that waiver.
