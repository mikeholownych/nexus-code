# WP-1103: Versioned Dataset Oracle Isolation

## Specification

**User story:** As an evaluation operator, I need versioned datasets to keep task stimulus separate from evaluator assertions, so that benchmark results cannot be inflated by exposing expected answers to the candidate.

**Acceptance criteria:**

- **AC1:** For a selected versioned example, the objective reaches the actual candidate prompt/provider-request boundary, while synthetic oracle-only assertion/validator sentinels are absent from the candidate prompt, request, argv, environment, stdin, and other candidate-visible input channels. Tests: `versioned dataset candidate receives stimulus without oracle sentinels`; `candidate launch envelope contains stimulus but no oracle data in argv env or stdin`.
- **AC2:** The candidate's staged workspace and declared filesystem/mount view expose the task fixture repository but do not expose the dataset task directory or hidden validator files by path or content. Test: `versioned dataset candidate workspace excludes evaluator files`.
- **AC3:** Dataset selection returns exactly the manifest-declared IDs for the requested `regression` or `benchmark` split and rejects unknown/empty splits or task IDs. Tests: `dataset selection returns exactly manifest-declared ids for each split`; `dataset selection refuses unknown ids and invalid splits`.
- **AC3a:** Loading rejects changes to oracle records or task-tree content after manifest freeze. Tests: `loader rejects oracle data changed after its manifest was frozen`; `loader rejects task data changed after its manifest was frozen`.
- **AC4:** After the candidate exits, the evaluator can still access the private oracle record and produce the expected score for the synthetic fixture. Test: `versioned dataset oracle scores after candidate exit`.
- **AC5:** Run the exact candidate CLI against a local fake provider that captures the actual request after prompt construction; record one candidate invocation and validator/scorer result for each of the six manifest-declared benchmark task IDs, with zero skipped or missing tasks. Record the source commit SHA and package archive SHA-256 separately, along with dataset version/split and the SHA-256 recomputed from the final integrated `core-v1/manifest.json`; do not reuse the prior branch's `05ee2fa33ae5f6d6afc35df2e003c913de3f7bf0f817d2f76c709c16fb640d43` as current evidence. Test/evidence: `installed candidate runs all public benchmark tasks with provenance`. This establishes execution coverage and request isolation, not model quality.

**Out of scope:** Modifying oracle semantics, held-out corpus data or custody; changing evaluator scoring; packaging the runtime; live inference against a real model/provider. AC5 uses the actual candidate CLI and prompt path with a local deterministic fake provider; the fake provider captures the request and returns a fixture response so the evaluator can score every declared benchmark task.

**Dependencies:** WP-1103 versioned dataset loader and runner integration; current runner claims are held by root after the prior claim was recorded stale and broken; a test seam for AC1, AC2 and AC4. AC5 requires an integrated exact-candidate benchmark run and is separate from the unit regression suite; packaged installed CLI behavior depends on WP-1104.

## AC2 plan addendum — actual candidate mount view

**Spec refinement:** AC2 requires evidence from the running dataset candidate's filesystem view, in addition to proving that the staged fixture workspace omits hidden files. The test must show that the candidate can see its declared `/workspace` mount, that the evaluator's dataset staging root is not mounted there, and that the absolute hidden validator path is unreadable.

**Chunk:** Extend the existing `versioned dataset candidate workspace excludes evaluator files` subtest in `cli/test/eval_dataset.test.ts`. Use the local fake provider to ask the real candidate to execute a read-only `run_command` probe. Capture the command's stdout and assert all three mount/path outcomes, while retaining the existing relative-path and sentinel assertions. No production sandbox change is planned unless the probe exposes a real leak.

**Reference retrieval:** XERJ `nexus-cli/sandbox.ts:183` (`probeBwrapSandbox`) demonstrates probing a real Bubblewrap process against an outside canary; `nexus-cli/tools.ts:1523` locates the production `run_command` wrapper, and `nexus-cli/sandbox.ts:219` provides the `wrapSandboxedCommand` signature. `eval/isolate.mjs` is outside the indexed CLI source; local source inspection at `agentSandboxArgv` confirmed the evaluator mounts `/tmp` as tmpfs and binds the candidate workspace at `/workspace`.

**Observed TDD:** The first focused run failed because the assertion matched the literal readable branch in the captured command rather than its stdout. The test was corrected to parse the `run_command` result. The focused dataset test then passed 3/3, with workspace mount present, dataset root mount absent, and the absolute validator path unreadable. This change adds dataset-specific acceptance evidence; it does not change production sandbox code.
