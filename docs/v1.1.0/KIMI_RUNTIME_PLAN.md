## Contracts and dependency order

First produce slice specifications with schema versions, storage/migration/rollback, explicit budgets, state transitions and executable test plans. Claim each slice and affected files under [CONCURRENCY.md](../v1.0.0/CONCURRENCY.md). Runtime implementation requires its own approved slice; this planning change is not implementation authority. No third-party or homelab service becomes required for standalone operation.

| Order / package | Required contract and integration | Dependencies / existing overlap |
| :--- | :--- | :--- |
| A / WP-1111 journal | Append-only, versioned canonical execution journal. Each event has event/schema ID, session/turn/operation/agent/parent IDs, per-stream sequence, timestamp, type, authority-context reference, before/after state digests and typed payload. Record intent, policy/approval, start, result, workspace/verification, failure, compaction and terminal transitions. Define durable commit/checkpoint boundaries and projection watermarks. Acknowledged transitions must survive restart. External effects cannot be made atomic by a journal: unknown outcomes require reconciliation. | WP-1102 sanitization before any write; INV-06. WP-1101 OTel, TUI and JSON/JSONL exports are projections, never competing truth. Reconcile existing state/journal storage in SPEC-OBSERVABILITY before coding; choose one transaction authority, not dual independent commits. |
| B / WP-1112 engine | One main/subagent step implementation for admission, model/tool invocation, authority, cancellation, persistence and outcome handling. Main vs. child differences are explicit policies; durable and ephemeral workers retain distinct lifetimes. Client-independent engine accepts typed commands and emits committed events. | WP-1111; REQ-AGT-111. WP-1106 remains operator pause/step behavior using this engine, not a replacement for the refactor. |
| B / WP-1116 failures | Typed `RETRY_SAME`, `RETRY_BACKOFF`, `REROUTE_PROVIDER`, `REPLAN`, `REAUTHENTICATE`, `WAIT_EXTERNAL`, `REQUIRE_OPERATOR`, `PERMANENT`. Map failure class, retry eligibility, effect certainty, attempt/deadline budget, backoff/jitter and operator reason. Distinguish 429 transient throttling from exhausted quota, 5xx/transport errors from invalid configuration/authentication. No blind quota retry or silent model substitution. | WP-1111; integrate into WP-1112 before engine acceptance; INV-02/04 and existing provider recovery. A retry budget exhaustion yields truthful blocked/failed disposition, never successful completion. |
| C / WP-1113 agents | Stable resumable agent ID, isolated context/history/runtime directory and typed result/evidence references. Capability manifest binds tools/effect classes, canonical workspace scope, network/credential scope, model class, delegation/depth and token/step/time budgets, verification requirement and durability. Child grants are intersections with parent grants; default delegation denied. Resume re-evaluates current authority and budgets, not saved approvals. | WP-1112/1116; WP-1109 scopes/provenance MEM-B/E and INV-01/05. Shared learned memory is not shared private history or authority. |
| C / WP-1114 tasks | Persistent TaskRegistry for shell work and agents: task/owner IDs, kind, work fingerprint, dependencies, resource claims, creation/start times, lifecycle, process handle plus boot/start identity, expected result, durable output/result references and completion event. Define queued/running/blocked/cancel-requested/cancelled/succeeded/failed/unknown transitions. Atomically claim equivalent work before start. Reconcile on reconnect/restart; PID alone is insufficient. | WP-1111/1112/1113/1116; existing operation store, process ownership, SUITE/GATEWAY-style resources and INV-02/06. Compaction uses registry metadata rather than conversational recollection. |
| C / WP-1117 context | Account separately for provider-measured input/output, estimated unreported delta, schemas, system instructions, durable/ephemeral context, reclaimable content, output reservation and safety margin. Record count source, request/content hash, model/tokenizer/worker identity and freshness. Components form a non-overlapping accounting partition: do not add measured totals to their already-included estimates. | WP-1111/1112; INV-04, WP-1107 schema costs, WP-1109 bounded memory and REQ-AGT-118/DEC-17. Changed workers or transformed prompts invalidate prior exact counts; unknown counts retain conservative admission or fail closed under strict counting. |
| D / WP-1118 compaction | `PROPOSED → INPUT_BOUND → ARCHIVE_COMMITTED → SUMMARY_GENERATED → SUMMARY_VALIDATED → CONTEXT_SWITCHED → COMMITTED`. Bind hashes of source, archive, summary, new context, objective ledger, active obligations and registry snapshot/version. Preserve archive-before-switch ordering. Concurrent task changes require version reconciliation, not a frozen stale snapshot. Validate required continuity fields; semantic summary quality still needs independent evaluation. | WP-1111/1112/1114/1117 and memory contracts; extend REQ-AGT-102. Recovery selects a valid committed generation or stops on persistence/corruption failure; never publish an unarchived context. |
| D / WP-1115 completion | Explicit gate at every main/child successful termination and resume. Resolve every mandatory objective/requirement, pending write/effect, current verification obligation, background task, unresolved decision, unconsumed failure and pending recovery. Return COMPLETE / CONTINUE / BLOCKED / FAILED with reasons and evidence refs. Snapshot workspace, ledger and registry generations atomically or recheck on change. | WP-1111/1112/1114/1116/1118; INV-03, WP-1103–1105 independent oracles. COMPLETE is lifecycle status, not automatically VERIFIED or REGRESSION_FREE. Cancellation, stagnation, step limits and budget exhaustion cannot be relabeled success. Continuation stays bounded and cannot override cancellation. |
| E / WP-1121 provenance | Manifest binds plugin ID/version/publisher, repository/revision, artifact digest, install time, declared permissions/effect classes/network origins/credential and filesystem scopes, signature/key ID and explicit local trust decision. Verify canonical signed bytes, artifact binding and revocation at load/use; pin trust roots and define offline revocation freshness policy. Update invalidates prior trust as required. | WP-1111 plus WP-1109 provenance, INV-01/05 and existing plugin audit. A signature identifies bytes/publisher, not safe behavior or permission. In-process full-user plugins cannot be honestly capability-confined by a manifest: isolate mediated execution before claiming enforcement, or retain explicit full-authority trust/disable restricted execution. |
| E / WP-1119 hooks | Versioned prompt/turn, pre/post/failure tool, agent start/stop, pre/post compaction and notification events. Typed inputs/results, deadlines, cancellation and recursion bounds. Telemetry/notification may fail open with an audit warning; enrichment behavior must be declared. Validation, authorization and release/verification hooks fail closed on crash, timeout, malformed/absent result. | WP-1111/1112/1115/1121; existing middleware rewrite audits. Re-run policy after argument changes; no hook bypass, silent authority elevation, forged verifier result or unbounded Stop loop. Hook code itself requires authorized execution and isolation; event delivery does not authorize effects. |
| F / WP-1120 ACP | Optional ACP adapter over the engine command boundary and journal projections. Pin supported protocol version/capability negotiation before implementation. Translate session, streaming, cancellation, approval and reconnect; unsupported operations explicitly fail. No protocol handler directly invokes tools or gains authority from a remote client. | WP-1111–1119/1121 contracts accepted; runtime/client separation first. WP-1101 remains telemetry, WP-1201 effect replay and WP-1203 inspector remain v1.2. ACP needs no cloud service and is disabled by default. |

A–D (WP-1111–WP-1118) precede discretionary TUI polish. WP-1101–WP-1110 retain all deliverables and gates; dependency modernization and evaluation can be planned alongside foundations without consuming v1.0 qualification capacity. This is a dependency order, not an unsupported delivery-date promise. WP-1302/1304 still own full context provenance and broader knowledge lifecycle.

| ID / package | Required executable acceptance and pass condition |
| :--- | :--- |
| ACC-KIMI-JOURNAL / WP-1111 | Inject kill/torn write/disk-full before and after every commit boundary, duplicate delivery, sequence gaps and concurrent writers. Reconstruct identical state digests and TUI/headless/export projections from the last committed prefix; detect corruption/gaps explicitly, never silently accept them. Disconnect tracing with no loss of canonical state. Secret canaries never enter durable journal, projections or crash dumps; oversize payloads use bounded protected references. Recovery never re-executes an effect. |
| ACC-KIMI-ENGINE / WP-1112 | Run identical main/child fixture scenarios for admission, malformed tool response, approval denial, hidden tool, abort, persistence failure and verification invalidation. Preserve v1 regression suites. |
| ACC-KIMI-AGENTS / WP-1113 | Restart/resume two isolated agents by ID; parent receives only typed results/authorized evidence. Test write/network/path escape, symlink replacement, sibling history access, revoked trust, forged saved approval, exhausted budgets and recursive delegation. All exceedances denied; grants never widen. Independent verifier cannot inherit implementation claims as its result. |
| ACC-KIMI-TASKS / WP-1114 | Race two equivalent task starts, compact while tests run, crash after spawn/before acknowledgement, reuse a PID, lose cancel acknowledgement and reconnect twice. At most one authorized start owns each claim; unknown effects stay visible and are not replayed. Outputs/terminal state survive restart, resource claims reconcile, and child processes are accounted for. Include dependency cycle/deadlock rejection and bounded output retention. |
| ACC-KIMI-COMPLETE / WP-1115 | Model says done with each mandatory obligation individually unresolved; also test forged/stale/irrelevant verifier receipts, queued steering, pending tasks and simultaneous workspace mutation/task completion. No successful terminal transition until the current bound obligation set is discharged. Evaluator crash/timeout blocks acceptance; zero false VERIFIED. A valid completed fixture terminates without a nudge loop; cancellation and exhausted recovery budgets terminate truthfully. |
| ACC-KIMI-FAILURE / WP-1116 | Table-driven 429 throttling/quota, timeout, 5xx, auth, bad request, worker change and unknown non-idempotent effect tests using a fake clock. | ACC-KIMI-CONTEXT / WP-1117 | Pinned tokenizer fixtures cover CJK/Hangul/kana, digits, base64, emoji, symbols, schemas, instructions and memory. | ACC-KIMI-COMPACT / WP-1118 | Kill and fail persistence at every named state, corrupt archive/summary/hash and change registry/ledger during compaction. Restart yields the prior committed context or fully validated new context, otherwise explicit persistence failure. Original content remains retrievable; objectives, verification obligations and running tasks survive two compactions plus kill/resume. No duplicate task or resurrected approval; independent long-task acceptance checks summary omissions. |
| ACC-KIMI-HOOKS / WP-1119 | Crash, timeout, malformed result, recursive event and permission-changing rewrite fixtures for every hook class. | ACC-KIMI-ACP / WP-1120 | Protocol conformance fixtures for negotiated version, unsupported calls, approvals, denied effects, cancellation, duplicate commands, disconnect/reconnect cursor and stale client state. If isolation is unavailable, deny restricted loading and label full-user-authority plugins honestly; signature success alone never passes this test. |

## Risks and required decisions before implementation

| Risk | Required mitigation / decision and acceptance link |
| :--- | :--- |
| Dual journals, schema drift and state migration lose truth | Choose canonical transaction owner, schema compatibility, bounded checkpoint/retention and migration rollback. Test old-state import, read-only inspection and interruption; ACC-KIMI-JOURNAL/COMPACT. Hashes detect inconsistency, not malicious rewrite without an external trust anchor. |
| Crash between effect and result or duplicate reconnect | Stable invocation/idempotency IDs plus explicit unknown state, claim fencing and reconciliation. Never promise exactly-once arbitrary external effects; ACC-KIMI-TASKS/FAILURE/ACP. |
| Provenance or hooks imply containment that does not exist | Distinguish publisher identity, operator trust and enforced execution grants. Resolve in-process extension isolation before restricted-mode support; ACC-KIMI-PLUGIN/HOOKS/AGENTS. |
| Compaction loses obligations; completion races changes | Versioned ledger/registry bindings, archive-first commit, stale-evidence invalidation and independent continuity checks; ACC-KIMI-COMPACT/COMPLETE. |
| Journal contains secrets or grows without bound | Pre-persistence sanitization, protected evidence references, bounded payload/storage quotas and explicit retention. Define how deletion/redaction preserves verifiable tombstones without claiming byte-lossless raw exports; WP-1102 and ACC-KIMI-JOURNAL. |
| Estimated tokens or feedback loops cause runaway work | Conservative admission, fresh measured identities, aggregate retry/delegation/hook budgets, cancellation and actionable terminal reasons; ACC-KIMI-CONTEXT/FAILURE/HOOKS. Never use a fixed cumulative step cap as proof of objective completion. |
| Expanded v1.1 scope delays baseline release or displaces existing work | Keep v1.0 qualification first; preserve every existing package and gate. Owner reviews effort/capacity and any explicit milestone change. No silent scope cut, qualification waiver or priority inversion. |
| Protocol/upstream assumptions drift | Pin ACP schema and Kimi source if used at slice start; isolate adapters and test compatibility. Current review provides design input, not a fresh upstream audit. |
