# G1.1-4 live measurement runbook (tool grammar matrix)

Status: **not run.** G1.1-4 (at least 99.5% valid tool-call JSON across supported endpoints) is NOT MET until this has been run at the exact-head gate and the evidence file is committed. Nothing in this document has been executed.

## What it measures
`eval/tool_grammar_matrix.mjs` drives the **exact installed candidate client** against one llama.cpp, one vLLM and one Ollama endpoint: 200 attempts per endpoint (50 per allow-listed tool, 5 of them hybrid `<think>` attempts). An endpoint passes only with `native_valid * 1000 >= attempts * 995`, zero schema-invalid and zero invalid. It writes immutable JSON evidence plus a detached `.sha256`.

## What it now binds (v1.1.4)
- the candidate **archive**: `archiveSha256` pin is mandatory and compared to the file;
- the installed runtime: every file matches the archive's `MANIFEST.sha256`; `.provenance.json` names the same archive digest and commit;
- the **checkout content**: `sourceTree` (the pinned `git rev-parse HEAD^{tree}`) is mandatory, the checkout's tree must equal it, every tracked file is re-hashed from disk against its blob id (defeats `assume-unchanged` / `skip-worktree`), its executable bit must equal the tree mode whatever `core.fileMode` says, untracked or ignored files are rejected, and `git replace` refs are rejected (every git call runs with `--no-replace-objects`). The evidence records `sourceCommit` and `sourceTree`.

## Steps
1. **Claim the shared inference host** (one host, DEC-16). The claim is machine-local and atomic and follows `docs/v1.0.0/CONCURRENCY.md` sections 2 and 3: `mkdir` is the lock, `owner.json` is JSON, and the release is logged.
   ```sh
   CLAIMS="$(git rev-parse --path-format=absolute --git-common-dir)/nexus-claims"; mkdir -p "$CLAIMS"
   REF="$(git branch --show-current)"; REF="${REF:-$(git rev-parse --short HEAD)}"   # detached worktree: record the short sha
   OUTCOME=aborted
   release_gateway() {   # runs on every exit path, including abort; logs one line, then releases
     printf '%s GATEWAY released by %s: G1.1-4 matrix %s\n' "$(date -u +%FT%TZ)" "$AGENT_NAME" "$OUTCOME" >> "$CLAIMS/../nexus-claims.log"
     rm -r "$CLAIMS/GATEWAY"
   }
   if mkdir "$CLAIMS/GATEWAY" 2>/dev/null; then
     trap release_gateway EXIT
     trap 'exit 130' INT TERM
     if ! printf '{"agent":"%s","branch":"%s","since":"%s","pid":%s}\n' \
          "$AGENT_NAME" "$REF" "$(date -u +%FT%TZ)" "$$" > "$CLAIMS/GATEWAY/owner.json"; then
       echo "claim directory created but owner.json could not be written; releasing the claim" >&2; exit 1
     fi
   else
     echo "GATEWAY is already claimed by: $(cat "$CLAIMS/GATEWAY/owner.json" 2>/dev/null || echo unknown)" >&2; exit 1
   fi
   ```
   Run the matrix (step 5) in this same shell and set `OUTCOME=pass` or `OUTCOME=fail` from its exit status before the shell exits. The `EXIT` trap then logs the line and removes the claim even if the run is interrupted or you `cd` elsewhere (`$CLAIMS` is absolute). If you cannot keep one shell, run the two lines inside `release_gateway` by hand at the end, with the outcome `pass`, `fail` or `aborted`.

   Do not run while another agent holds the claim. A claim older than 24 h whose PID is gone may be broken only as CONCURRENCY.md section 2 describes (record it in the log first).

   **Isolation (CONCURRENCY.md section 3).** Run from a dedicated `git worktree` of the exact head (not a shared checkout), with a throwaway `HOME` so the run never reads `~/.config/nexus/credentials.json` or writes sessions into the operator's home:
   ```sh
   git worktree add ../nexus-wt-g114 <exact-head-sha>
   export HOME="$(mktemp -d)"
   ```
   The private config carries endpoints only; if an endpoint needs a key, supply it through the environment of the run, never in the config or the repo.

2. **Build the candidate** from the exact head under test; the checkout must be clean at that head and contain no untracked or ignored files. Record: `sourceCommit=$(git rev-parse HEAD)`, `sourceTree=$(git rev-parse HEAD^{tree})`.
3. **Install it** with the real installer so `.provenance.json` (`method: installer`, `archiveSha256`, `revision`) is written, and keep the archive: `archiveSha256=$(sha256sum nexus-<version>.tar.gz | cut -d' ' -f1)`.
4. **Write a private config** (outside the repo, mode 0600; it names endpoints only, never credentials; server flags must not contain keys or tokens):
   ```json
   {
     "archivePath": "/abs/nexus-<version>.tar.gz",
     "archiveSha256": "<sha256>",
     "installRoot": "/abs/installed/nexus",
     "candidateCheckoutRoot": "/abs/checkout",
     "sourceCommit": "<40 hex>",
     "sourceTree": "<40 hex>",
     "outputPath": "/abs/docs/evidence/v1.1.4/wp-1107-provider-matrix.json",
     "providers": [
       { "provider": "llamacpp", "serverKind": "llamacpp", "endpointUrl": "http://<owner-llama-host>:<port>/v1",
         "serverVersion": "<build>", "imageDigest": "sha256:<64 hex>", "modelName": "<name>", "modelDigest": "sha256:<64 hex>",
         "contextSize": 8192, "sampling": { "temperature": 0, "max_tokens": 1024 }, "toolChoice": "auto",
         "serverFlags": ["--jinja"], "compatibilityMode": "<pinned text>" }
       // plus one entry each for "vllm" and "ollama" (exactly three providers are required)
     ]
   }
   ```
   The llama.cpp entry is the owner's host. The matrix refuses to start unless every pinned field is present and the endpoint identifies as the configured kind.
5. **Run:**
   ```bash
   node eval/tool_grammar_matrix.mjs --config /abs/private-config.json
   ```
   Exit 0 only if every endpoint passes. Stdout is a non-secret summary.
6. **Commit the evidence** (`outputPath` and its `.sha256`), reference it from the release notes, update the `G1.1-4` row in `FINDINGS.md` with the exact integer counts, and release the `GATEWAY` claim.

If an endpoint misses, the evidence is still written as a failed result; G1.1-4 stays NOT MET and the miss is reported, not rounded.
